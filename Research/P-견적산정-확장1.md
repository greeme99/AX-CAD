# 2D, 3D CAD drawing 파일 및 데이터로 한국표준 견적서를 작성할 수 있도록 확장 가이드 및 개발 방법론 서치해서 가이드 해줘. 중요한 것은 반드시 근거가 있는 소스를 찾아서 신뢰할수 있고 바로 코딩에 사용할 수 있도록 개발 가이드 만든다

아래 가이드는 **2D/3D CAD 파일과 도면 데이터로 한국표준 견적서를 자동 작성**하기 위한 개발 방법론입니다. 핵심은 DXF의 엔티티/레이아웃 구조와 STEP의 부품·어셈블리·PMI 개념을 그대로 비용산정 데이터로 매핑하는 것이며, 이를 위해 DXF는 Autodesk 공식 문서와 ezdxf 구조를 기준으로, 3D는 STEP AP242와 OCCT XDE 기준으로 설계하는 게 가장 안전합니다.[^1][^2][^3][^4][^5]

## 1. 구현 목표

- **입력**: DXF, STEP, IGES, PDF 도면 메타데이터, 사내 기준단가표, 공정표, 재료규격표.
- **출력**: 한국표준 형식의 견적서 초안, 산출근거표, 수량산출표, 공정별 비용표.
- **핵심 원칙**: “도면 객체 → 제조가능 부품/공정 → 수량 → 단가 → 견적서 항목”으로 이어지는 추적성을 남깁니다.
- **실행 방식**: 초기에는 규칙기반, 이후에는 AI 보조 추출을 붙이되 최종 산출은 규칙과 검증으로 고정합니다.


## 2. 근거가 되는 파일 구조

DXF는 AutoCAD의 모든 정보를 태깅된 데이터로 표현하며, 그룹 코드 기반 구조를 가집니다. ezdxf에서는 그래픽 엔티티가 modelspace, paperspace, block layout에 저장되고, `doc.modelspace()`, `doc.paperspace()`, `doc.blocks`로 접근합니다.[^6][^3][^7][^4][^8][^1]
이 말은 곧 \*\*견적 엔진이 먼저 읽어야 하는 것은 “파일”이 아니라 “레이아웃/블록/엔티티/속성”\*\*이라는 뜻입니다.[^3][^4]

STEP는 ISO 10303 기반으로 parts, assemblies, PMI, GD\&T를 표현할 수 있어, 3D 견적에서는 형상 부피만이 아니라 조립 관계와 공차/주석 정보를 반영할 수 있습니다. OCCT XDE는 STEP/IGES를 읽고 쓰며 이름, assembly, validation properties 같은 구조화 정보를 다룰 수 있어 3D 견적용 백엔드에 적합합니다.[^2][^5]

## 3. 견적 산정 파이프라인

### 3.1 2D 파이프라인

1. DXF 업로드.
2. 문서/레이아웃/블록/엔티티 파싱.
3. 도형 분류: 선재, 절곡, 구멍, 외곽선, 문자, 치수.
4. 가공 규칙 적용: 절단 길이, 면적, 개수, 반복수, 낭비율.
5. 공정 매핑: 레이저 절단, CNC, 프레스, 표면처리, 조립.
6. 산출표 작성: 재료비, 가공비, 외주비, 경비, 마진.

### 3.2 3D 파이프라인

1. STEP/IGES 업로드.
2. Part/Assembly 구조 읽기.
3. 형상 계측: 부피, 표면적, 외형치수, 개수.
4. PMI/GD\&T 추출 가능 시 품질비용 계상.
5. 가공 경로 또는 제조 공정 매핑.
6. 견적 항목 자동 생성.

### 3.3 하이브리드 파이프라인

- 2D 도면에서 부품명을 잡고,
- 3D 형상에서 수량·부피·표면적을 보정하고,
- BOM과 공정표를 통해 최종 견적서로 합칩니다.


## 4. 데이터 모델 설계

### 핵심 엔티티

- `drawing_document`
- `drawing_entity`
- `drawing_block`
- `model_feature`
- `part_candidate`
- `process_rule`
- `cost_item`
- `quote_header`
- `quote_line`
- `quote_line_source_map`
- `price_master`
- `material_master`
- `process_master`
- `revision_snapshot`


### 관계 요약

- 1개 도면 문서에는 여러 레이아웃과 엔티티가 존재.
- 엔티티는 부품 후보와 1:N 또는 N:M으로 연결.
- 부품 후보는 공정 규칙을 통해 비용항목으로 변환.
- 비용항목은 견적서 헤더 아래 라인으로 저장.


## 5. 비용 산정 규칙

### 5.1 2D 기준

- **절단 길이**: LINE, LWPOLYLINE, ARC의 총 길이.
- **면적**: 폐곡선 내부 면적.
- **구멍 수**: CIRCLE, ARC 닫힘 조건.
- **반복수**: BLOCK INSERT 횟수.
- **문자/치수**: 도면 표기물은 참고용, 공정비에 직접 반영하지 않음.
- **재료 수율**: 외곽 면적 대비 시트 규격 효율.


### 5.2 3D 기준

- **부피**: 재료비 기본 단위.
- **표면적**: 도장/코팅비 계산.
- **구멍/리브/보스 수**: 가공 난이도 가중치.
- **어셈블리 부품 수**: 조립 공수 산정.
- **PMI/GD\&T**: 검사 공수와 품질비 가중치.


## 6. 바로 코딩 가능한 추출 규칙

### 6.1 DXF 엔티티 매핑 규칙

| DXF 엔티티 | 해석 | 견적 활용 |
| :-- | :-- | :-- |
| LINE | 직선 절단 | 절단 길이 |
| LWPOLYLINE | 외곽선/절곡선 | 길이, 면적, 반복 |
| CIRCLE | 홀, 구멍 | 천공 수량 |
| ARC | 곡선 절단 | 곡선 길이 |
| TEXT/MTEXT | 도면번호/부품명 | 메타데이터 추출 |
| INSERT | 블록 반복 | 수량 곱셈 |
| DIMENSION | 치수 주석 | 검증용 |
| HATCH | 면적 영역 | 재료 산정 보조 |

ezdxf는 엔티티가 레이아웃과 블록에 저장되고, 엔티티의 `dxf` 속성으로 레이어, 핸들, 속성값을 읽을 수 있으므로 규칙 엔진 작성이 쉽습니다.[^7][^9][^3]

### 6.2 STEP/3D 매핑 규칙

| STEP/3D 항목 | 해석 | 견적 활용 |
| :-- | :-- | :-- |
| Part | 단품 | 재료/가공 단가 |
| Assembly | 조립품 | 조립공수 |
| Shape volume | 부피 | 재료비 |
| Surface area | 표면적 | 도장/후처리 |
| PMI/GD\&T | 공차/검사 | 품질비 |

STEP는 parts, assemblies, PMI를 표현하고, semantic PMI는 기계가 해석 가능한 형태로 downstream 제조/검사에 유용합니다. OCCT XDE는 shape names, assemblies, validation properties를 읽고 쓸 수 있어 이 매핑에 잘 맞습니다.[^5][^2]

## 7. 개발 방법론

### 7.1 MVP 우선순위

1. DXF 업로드와 파싱.
2. 엔티티 분류.
3. 길이/개수/면적 산출.
4. 단가표 연결.
5. 견적서 출력.
6. STEP 연동.
7. PMI/공차 반영.

### 7.2 구현 원칙

- **규칙 엔진과 파서 분리**.
- **도면 메타데이터와 가격표 분리**.
- **산출근거와 결과값 분리 저장**.
- **AI는 추출 보조, 최종 수치는 검증 엔진으로 확정**.
- **모든 계산은 revision snapshot 기준**으로 재현 가능해야 함.


### 7.3 추천 스택

- Parser: Python + ezdxf.
- 3D kernel: OCCT / pythonocc 계열.
- Rule engine: Python rules + JSON/YAML 규칙.
- DB: PostgreSQL.
- API: FastAPI.
- Report: HTML/PDF template + Excel export.


## 8. API 설계 초안

### 8.1 업로드

`POST /api/quote/import/dxf`

- 입력: file, project_id, doc_no
- 출력: entity summary, warning list, quote draft id


### 8.2 3D 업로드

`POST /api/quote/import/step`

- 입력: file, part_no, revision
- 출력: part metrics, assembly structure, quote draft id


### 8.3 견적 생성

`POST /api/quote/generate`

- 입력: source id, rule set id, price master id
- 출력: quote header, lines, total amount


### 8.4 근거 조회

`GET /api/quote/{quote_id}/trace`

- 입력 없음
- 출력: line별 source entity, rule id, calculation log


### 8.5 검증

`POST /api/quote/{quote_id}/validate`

- 입력: quote id
- 출력: mismatch, missing price, duplicate items, approval status


## 9. 신뢰 가능한 소스 기반 구현 포인트

- DXF는 Autodesk 공식 문서에서 태그 데이터와 ASCII/binary 형식을 확인할 수 있습니다.[^10][^11][^1]
- ezdxf는 modelspace, paperspace, blocks, entity layout을 공식 문서로 제공하므로 파서 구조를 그대로 따를 수 있습니다.[^4][^8][^3][^7]
- STEP는 NIST 자료에서 parts, assemblies, PMI, AP242 지원과 활용 목적이 정리되어 있습니다.[^2]
- OCCT XDE는 STEP/IGES의 읽기/쓰기와 assembly, validation properties, shape names를 처리합니다.[^5]

## 11. 바로 코딩할 때 주의점

- 블록 INSERT는 반복 수량 산정의 핵심입니다.[^8][^4]
- 모델스페이스와 페이퍼스페이스를 혼동하면 견적 수량이 틀어집니다.[^3][^7]
- 3D는 형상 정보만이 아니라 assembly와 PMI를 같이 봐야 정확합니다.[^2][^5]
- 최종 견적서는 반드시 **근거 추적표**를 함께 저장해야 감사와 재현이 가능합니다.
