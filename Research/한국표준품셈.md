CAD 도면에서 **수량(QTO)** 을 추출하고, 이를 2026년 적용 건설공사 표준품셈의 **품셈 항목·투입량 기준**과 매핑한 뒤, 표준시장단가·노임·기계경비를 적용해 DB에 적산하는 구조가 핵심입니다. 다만 표준품셈은 현재 공공데이터포털에 **PDF 파일데이터**로 제공되며, 공식적인 구조화된 품셈 REST API는 확인되지 않으므로 “PDF/엑셀 정제 + 자체 API화”가 현실적인 연계 방식입니다. ## 2. 전체 시스템 구조

권장 아키텍처는 다음 5계층입니다.

```text
CAD/BIM 도면
  └─ AutoCAD/Revit/Civil 3D/ArchiCAD
        └─ 수량산출(QTO) 엔진
             └─ 공종·부위·규격별 수량 JSON/CSV
                  └─ 품셈 매핑 규칙 엔진
                       └─ 표준품셈 DB
                            └─ 단가·물가·노임·기계경비 DB
                                 └─ 공사비 시뮬레이션 API/대시보드
```

- **CAD 계층**: 도면 레이어, 블록, 속성, Revit 패밀리/파라미터를 표준화합니다.
- **QTO 계층**: 벽체 면적, 콘크리트 체적, 철근 중량, 도장 면적 등을 산출합니다.
- **매핑 계층**: CAD 객체·공법·규격을 표준품셈의 품셈번호와 연결합니다.
- **적산 계층**: 수량 × 품셈 투입량 × 단가로 노무비·재료비·경비를 계산합니다.
- **시뮬레이션 계층**: 물가, 지역, 공기, 손실률, 설계변경 시나리오를 반영합니다.

## 3. 품셈 DB 설계

PDF를 그대로 저장하지 말고, 아래처럼 **정규화된 품셈 마스터**로 적재해야 합니다.

| 테이블 | 주요 컬럼 | 설명 |
|---|---|---|
| `costbook_version` | `version`, `effective_from`, `notice_no`, `published_at` | 2026년판, 고시번호, 적용일 관리 |
| `work_item` | `item_code`, `name`, `unit`, `category`, `spec` | 품셈 항목, 예: 콘크리트 타설 |
| `work_item_resource` | `item_code`, `resource_type`, `resource_code`, `qty_per_unit` | 단위당 노무·재료·장비 투입량 |
| `resource_master` | `resource_code`, `name`, `unit`, `type` | 인력·자재·장비 마스터 |
| `price_master` | `resource_code`, `price_date`, `region`, `price`, `source` | 표준시장단가 또는 실제 단가 |
| `cad_object_map` | `cad_category`, `layer`, `family`, `type`, `work_item_code`, `conversion_rule` | CAD 객체와 품셈 연결 |
| `quantity_extract` | `project_id`, `element_id`, `work_item_code`, `qty`, `unit`, `source_file` | CAD에서 추출한 수량 |
| `estimate_line` | `project_id`, `scenario_id`, `work_item_code`, `qty`, `labor_cost`, `material_cost`, `equipment_cost` | 산출 내역 |
| `scenario` | `scenario_id`, `price_date`, `region`, `waste_rate`, `productivity_factor` | 시뮬레이션 조건 |

핵심 계산식은 다음과 같습니다.

\[
\text{공종비용} = \text{수량} \times \sum_{r} (\text{품셈 투입량}_r \times \text{단가}_r)
\]

여기서 \(r\)은 해당 품셈 항목의 노무·재료·장비 자원입니다. 품셈의 본질은 공종별 인력·장비·재료의 단위 작업당 투입량과 작업 기준을 제공하는 것이므로, 이 구조가 원문의 논리와 일치합니다. [data.go](https://www.data.go.kr/data/15034638/fileData.do?recommendDataYn=Y)

## 4. CAD 연동 방법

### AutoCAD 중심

2D 도면이라면 레이어·블록·속성 기반 수량 추출이 현실적입니다.

- 레이어 표준: `A-WALL`, `S-CONC`, `E-LIGHT`처럼 분류 체계를 고정합니다.
- 블록 속성: 자재명, 규격, 수량, 높이, 두께 등을 속성 태그로 강제합니다.
- 추출 대상: 폴리라인 면적, 폴리라인 길이, 블록 수, 속성값, 3D 솔리드 체적.
- 산출 예: 벽체 폴리라인 길이 × 도면 높이 = 벽체 면적, 이후 미장·도장 품셈과 매핑.

### Revit/BIM 중심

Revit은 IFC 기반 개방형 BIM 교환을 지원하며, IFC4·IFC2x3 등 표준 스키마로 내보낼 수 있습니다.  IFC의 `QuantitySet`에는 벽·슬래브 등 요소별 수량 속성이 포함될 수 있고, Autodesk는 수량 속성이 설계 도구에서 정확히 정의되어야 모델 기반 산출이 가능하다고 안내합니다. [help.autodesk](https://help.autodesk.com/cloudhelp/2025/ENU/Revit-DocumentPresent/files/GUID-6708CFD6-0AD7-461F-ADE8-6527423EC895.htm)

| 도구 | 연동 방식 | 산출물 |
|---|---|---|
| Revit | Revit API 또는 Dynamo로 Element, Parameter, Quantity 추출 | JSON/CSV 수량 명세 |
| Revit → IFC | IFC4 내보내기 후 `IfcOpenShell`로 파싱 | 요소별 수량·분류·속성 |
| AutoCAD | .NET API, AutoLISP, ObjectARX 또는 DXF 파싱 | 레이어·블록·폴리라인 수량 |
| Civil 3D | COGO Point, Alignment, Surface, Corridor 객체 API | 토공·도로 공종 수량 |
| ArchiCAD | IFC 내보내기 또는 ArchiCAD API | 건축 요소 수량 |

## 5. 바이브코딩 구현 절차

### 1단계: 원천 수집

1. CODIL에서 2026년 표준품셈 원문·개정사항 PDF를 수집합니다. [codil.or](https://www.codil.or.kr/helpdesk/read.do?bbsId=BBSMSTR_900000000202&nttId=13261&searchWrd=)
2. 공공데이터포털의 표준품셈 파일데이터 메타데이터와 라이선스를 기록합니다. [data.go](https://www.data.go.kr/data/15034638/fileData.do?recommendDataYn=Y)
3. 표준시장단가와 기계경비 산출표를 별도 소스로 수집합니다. [cak.or](https://www.cak.or.kr/lay1/bbs/S1T43C46/A/15/list.do)

### 2단계: PDF → 구조화 데이터

- `pdfplumber` 또는 `Camelot`으로 표 추출
- 페이지·장·절·품셈번호·품명·단위·재료/노무/장비 투입량 분리
- OCR이 필요한 스캔 PDF는 별도 검수 큐로 분리
- 추출 결과는 반드시 원문 PDF 페이지 번호와 대조 검증

권장 검증 규칙:

- 품셈번호 중복 검사
- 단위 누락 검사
- 재료·노무·장비 투입량의 음수·이상치 검사
- 개정 전후 품셈번호 비교
- 표준시장단가의 기준일과 품셈 적용일 정합성 검사

### 3단계: DB 적재

PostgreSQL 기준 예시입니다.

```sql
CREATE TABLE work_item (
  id BIGSERIAL PRIMARY KEY,
  version_id BIGINT NOT NULL,
  item_code VARCHAR(50) NOT NULL,
  name TEXT NOT NULL,
  unit VARCHAR(20) NOT NULL,
  category VARCHAR(100),
  spec TEXT,
  effective_from DATE NOT NULL,
  UNIQUE(version_id, item_code)
);

CREATE TABLE work_item_resource (
  id BIGSERIAL PRIMARY KEY,
  work_item_id BIGINT REFERENCES work_item(id),
  resource_type VARCHAR(20) NOT NULL, -- LABOR, MATERIAL, EQUIPMENT
  resource_code VARCHAR(50),
  resource_name TEXT,
  unit VARCHAR(20),
  qty_per_unit NUMERIC(18,6) NOT NULL
);

CREATE TABLE cad_object_map (
  id BIGSERIAL PRIMARY KEY,
  cad_category VARCHAR(100),
  cad_family VARCHAR(100),
  cad_type VARCHAR(100),
  layer_pattern VARCHAR(200),
  work_item_code VARCHAR(50),
  quantity_type VARCHAR(30), -- AREA, VOLUME, LENGTH, COUNT, WEIGHT
  conversion_factor NUMERIC(18,6) DEFAULT 1,
  waste_rate NUMERIC(6,4) DEFAULT 0
);
```

### 4단계: CAD 수량 추출 예시

Revit에서 IFC를 거치지 않고 직접 수량을 뽑는 경우, Dynamo 또는 Python/Revit API로 아래 JSON을 만듭니다.

  "elements": [

      "element_id": "331245",

## 6. API 연계의 현실적 선택지

| 방식 | 가능 여부 | 장점 | 한계 |
|---|---|---|---|
| 공공데이터포털 표준품셈 파일 다운로드 | 가능 | 무료, 공식 원천, CC-Zero 표기  [data.go](https://www.data.go.kr/data/15034638/fileData.do?recommendDataYn=Y) | PDF라서 별도 ETL 필요 |
| CODIL 자료 다운로드 | 가능 | 최신 공고·개정사항 확보 용이  [codil.or](https://www.codil.or.kr/helpdesk/read.do?bbsId=BBSMSTR_900000000202&nttId=13261&searchWrd=) | 화면/PDF 기반이므로 자동화 안정성 관리 필요 |
| 자체 품셈 REST API 구축 | 권장 | CAD·ERP·적산시스템과 재사용 가능 | 초기 데이터 정제 비용 발생 |
| 건설CALS OpenAPI | 보조 가능 | 공사정보·설계변경 등 공사 관리 정보 연계  [calspia.go](https://www.calspia.go.kr/io/openapi/gid/selectOpenApiSvcListView.do) | 품셈 원문 API는 아님 |
| 상용 적산·BIM 솔루션 API | 가능 | 검증된 산출 로직 활용 | 라이선스·비용·벤더 종속 |

따라서 “공공 API 하나로 품셈을 실시간 호출”하는 설계보다는, **공식 PDF를 주기적으로 수집 → 검증된 품셈 DB로 적재 → 자체 API로 서비스**하는 방식이 안전합니다. 공공데이터포털도 해당 데이터를 PDF 파일데이터로 명시하고 있습니다. [data.go](https://www.data.go.kr/data/15034638/fileData.do?recommendDataYn=Y)

## 7. 데이터 품질·감사 체계

공사비 시뮬레이션은 산출 근거가 핵심이므로 다음을 반드시 남겨야 합니다.

- `source_url`: CODIL·data.go.kr 원문 URL
- `source_file_hash`: PDF SHA-256
- `page_no`: 해당 품셈의 원문 페이지
- `version`: 2026, 정오표 반영 여부
- `extract_method`: PDF 파싱, 수기 검수, OCR 여부
- `reviewer`: 검수자
- `approved_at`: 승인일시
- `calc_trace`: 수량 → 품셈 → 단가 → 비용 계산 로그

이렇게 하면 “왜 이 공사비가 나왔는가”를 품셈 원문 페이지, CAD 객체, 단가 기준일까지 추적할 수 있습니다.
