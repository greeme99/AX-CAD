# 실제 화면 설계서 상세히 작성하고, 오픈소스 기하 커널 연동 코드 생성하고, MVP 개발 태스크 정의하고, PostgreSQL 기준 DDL 초안 생성해서 개발 시나리오에 맞체 정리해줘

아래는 **중견제조기업용 CAD 시스템 개발 패키지**입니다. 실제 화면 설계서, 오픈소스 기하 커널 연동 예시, MVP 태스크와 일정, PostgreSQL DDL 초안을 **개발 시나리오 순서대로** 묶어 정리했습니다. DXF 문서 관리는 ezdxf의 `readfile()`, `save()`, `write()`, `export_json_tags()` 같은 표준 API를 기준으로 잡고, DB는 PostgreSQL의 PRIMARY KEY, UNIQUE, CHECK, FOREIGN KEY 규칙에 맞춰 설계했습니다.[^1][^2]

## 1. 개발 시나리오

### 시나리오 A: 2D 도면 중심 MVP

- 사용자가 DXF 도면을 업로드한다.
- 시스템이 도면을 파싱하고 2D 뷰어에 렌더링한다.
- 사용자는 레이어 on/off, 줌, 팬, 객체 선택, 치수 확인을 수행한다.
- 저장 시 Revision이 생성되고 감사로그가 남는다.


### 시나리오 B: 3D 확장

- 2D 스케치에서 폐곡선을 선택한다.
- OCCT 기반 커널이 Extrude/Boolean을 수행한다.
- 결과를 STEP으로 내보내고 PLM 또는 PDM 저장소에 등록한다.


### 시나리오 C: 제조 연계

- 도면 속성에서 품번, 규격, 수량을 추출한다.
- BOM을 생성한다.
- ERP/MES로 연동 API를 호출한다.


## 2. 화면 설계서

### 2.1 로그인 화면

- 목적: 권한 기반 접근 제어.
- 주요 필드: 사용자ID, 비밀번호, OTP 선택.
- 버튼: 로그인, 비밀번호 재설정.
- 검증: 계정 잠금, 비활성 계정 차단.
- 출력: 토큰, 사용자 역할, 최근 사용 프로젝트.


### 2.2 프로젝트 목록 화면

- 목적: 도면/문서 작업 단위 선택.
- 구성: 프로젝트 카드 또는 테이블, 검색, 필터, 최근 열람.
- 필드: 프로젝트명, 고객사, 제품군, 상태, 담당자, 개정 수.
- 기능: 생성, 복제, 아카이브, 권한 설정.


### 2.3 도면 목록 화면

- 목적: 프로젝트 내 도면 관리.
- 구성: 문서번호, 제목, 타입, 현재 Revision, 상태, 승인여부.
- 기능: 업로드, 새 도면, 변경요청, 내보내기.
- 검증: 중복 문서번호 금지, 필수 메타데이터 누락 방지.


### 2.4 2D 뷰어 화면

- 목적: 도면 열람과 검토.
- 구성: 좌측 레이어 패널, 중앙 캔버스, 우측 속성 패널, 하단 상태바.
- 기능: 줌, 팬, 객체 선택, 하이라이트, 거리 측정, 인쇄 미리보기.
- 표시: 좌표, 단위, 활성 레이어, 스냅 상태.


### 2.5 2D 편집 화면

- 목적: 선/원/호/문자/치수 편집.
- 구성: 툴바, 작업영역, 스냅 표시, 속성창.
- 기능: 그리기, 수정, 삭제, 복사, 이동, 회전, 배열.
- 검증: 닫힌 형상 여부, 교차 여부, 단위 일관성.


### 2.6 스냅/치수 패널

- 목적: 제도 정밀도 보강.
- 항목: Endpoint, Midpoint, Center, Intersection, Grid Snap.
- 기능: 스냅 반경 설정, 마커 색상, 치수 스타일.
- 운영: 기본값은 설계표준에서 내려옴.


### 2.7 Revision/승인 화면

- 목적: 변경 이력과 승인 관리.
- 구성: 변경요청 목록, 승인자, 승인 상태, 코멘트.
- 기능: 비교, 승인, 반려, 롤백.
- 검증: 승인 완료 전 외부 연동 제한.


### 2.8 BOM 화면

- 목적: 도면 기반 자재명세서 관리.
- 구성: 품번, 품명, 규격, 수량, 단위, 원천 도형 참조.
- 기능: 자동 추출, 수동 수정, ERP 전송, CSV 출력.
- 검증: 품번 중복, 수량 음수 금지.


### 2.9 관리자 화면

- 목적: 기준정보와 연동 관리.
- 구성: 사용자, 역할, 템플릿, 라이브러리, 로그, 작업 큐.
- 기능: 권한 부여, 시스템 설정, 연동 재시도, 오류 추적.


## 3. 오픈소스 기하 커널 연동 코드

아래는 **Python + ezdxf + OCCT 연동**을 상정한 최소 구조 예시입니다. ezdxf는 DXF 읽기/쓰기와 JSON tags export/load를 지원하고, OCCT는 XDE를 통해 STEP/IGES 및 구조화된 CAD 데이터를 다루는 쪽이 적합합니다.[^3][^4][^1]

```python
from dataclasses import dataclass
from pathlib import Path

import ezdxf

@dataclass
class DxfImportResult:
    path: str
    layers: list[str]
    entity_count: int

class DxfService:
    def load(self, file_path: str) -> DxfImportResult:
        doc = ezdxf.readfile(file_path)
        msp = doc.modelspace()
        layers = sorted({e.dxf.layer for e in msp if hasattr(e.dxf, "layer")})
        return DxfImportResult(
            path=file_path,
            layers=layers,
            entity_count=len(msp),
        )

    def export(self, doc, out_path: str):
        doc.saveas(out_path)

    def to_json_tags(self, file_path: str) -> str:
        doc = ezdxf.readfile(file_path)
        return ezdxf.document.export_json_tags(doc, compact=True)
```

### 연동 포인트

- **DXF import**는 ezdxf로 처리한다.
- **기하 연산**은 OCCT로 보낸다.
- **메타데이터**는 Document/Revision/BOM 테이블과 매핑한다.
- **STEP/IGES export**는 OCCT XDE 계층을 우선 검토한다.[^4][^3]

## 6. PostgreSQL DDL 초안

PostgreSQL은 PRIMARY KEY, UNIQUE, CHECK, FOREIGN KEY를 통한 참조 무결성과 제약 조건 설계를 권장합니다. 아래 DDL은 MVP 기준 핵심 테이블만 넣은 초안입니다.[^2][^5]

```sql
create table users (
    user_id bigserial primary key,
    login_id varchar(100) not null unique,
    user_name varchar(100) not null,
    email varchar(200) unique,
    password_hash text not null,
    is_active boolean not null default true,
    created_at timestamptz not null default now()
);

create table roles (
    role_id bigserial primary key,
    role_code varchar(50) not null unique,
    role_name varchar(100) not null
);

create table user_roles (
    user_id bigint not null references users(user_id) on delete cascade,
    role_id bigint not null references roles(role_id) on delete restrict,
    primary key (user_id, role_id)
);

create table projects (
    project_id bigserial primary key,
    project_code varchar(50) not null unique,
    project_name varchar(200) not null,
    customer_name varchar(200),
    status varchar(30) not null default 'ACTIVE',
    created_by bigint references users(user_id),
    created_at timestamptz not null default now()
);

create table documents (
    document_id bigserial primary key,
    project_id bigint not null references projects(project_id) on delete cascade,
    doc_no varchar(100) not null,
    doc_type varchar(30) not null,
    title varchar(200) not null,
    status varchar(30) not null default 'DRAFT',
    current_revision_id bigint,
    created_by bigint references users(user_id),
    created_at timestamptz not null default now(),
    unique (project_id, doc_no)
);

create table document_revisions (
    revision_id bigserial primary key,
    document_id bigint not null references documents(document_id) on delete cascade,
    revision_no varchar(20) not null,
    file_format varchar(20) not null,
    file_path text not null,
    checksum varchar(128) not null,
    revision_note text,
    created_by bigint references users(user_id),
    created_at timestamptz not null default now(),
    unique (document_id, revision_no)
);

alter table documents
    add constraint fk_documents_current_revision
    foreign key (current_revision_id)
    references document_revisions(revision_id)
    on delete set null;

create table drawings (
    drawing_id bigserial primary key,
    document_id bigint not null references documents(document_id) on delete cascade,
    sheet_no varchar(50),
    paper_size varchar(20),
    scale varchar(20),
    unit varchar(20) not null,
    created_at timestamptz not null default now()
);

create table layers (
    layer_id bigserial primary key,
    drawing_id bigint not null references drawings(drawing_id) on delete cascade,
    layer_name varchar(100) not null,
    color_code varchar(20),
    line_type varchar(50),
    is_visible boolean not null default true,
    unique (drawing_id, layer_name)
);

create table entities (
    entity_id bigserial primary key,
    revision_id bigint not null references document_revisions(revision_id) on delete cascade,
    entity_type varchar(50) not null,
    layer_id bigint references layers(layer_id) on delete set null,
    geometry_ref text not null,
    attr_json jsonb not null default '{}'::jsonb,
    created_at timestamptz not null default now()
);

create table dimensions (
    dimension_id bigserial primary key,
    drawing_id bigint not null references drawings(drawing_id) on delete cascade,
    dim_type varchar(30) not null,
    value_numeric numeric(18,6),
    unit varchar(20) not null,
    style_json jsonb not null default '{}'::jsonb
);

create table constraints (
    constraint_id bigserial primary key,
    drawing_id bigint not null references drawings(drawing_id) on delete cascade,
    constraint_type varchar(50) not null,
    target_entity_ids jsonb not null,
    params_json jsonb not null default '{}'::jsonb
);

create table parts (
    part_id bigserial primary key,
    part_no varchar(100) not null unique,
    part_name varchar(200) not null,
    spec varchar(200),
    unit varchar(20) not null default 'EA',
    is_active boolean not null default true
);

create table assemblies (
    assembly_id bigserial primary key,
    assembly_no varchar(100) not null unique,
    assembly_name varchar(200) not null,
    revision varchar(20),
    is_active boolean not null default true
);

create table bom_headers (
    bom_header_id bigserial primary key,
    document_id bigint references documents(document_id) on delete cascade,
    bom_no varchar(100) not null unique,
    source_type varchar(30) not null,
    created_at timestamptz not null default now()
);

create table bom_items (
    bom_item_id bigserial primary key,
    bom_header_id bigint not null references bom_headers(bom_header_id) on delete cascade,
    item_no integer not null,
    part_id bigint references parts(part_id) on delete restrict,
    assembly_id bigint references assemblies(assembly_id) on delete restrict,
    qty numeric(18,6) not null check (qty > 0),
    unit varchar(20) not null,
    source_entity_id bigint references entities(entity_id) on delete set null,
    unique (bom_header_id, item_no),
    check (
        (part_id is not null and assembly_id is null)
        or
        (part_id is null and assembly_id is not null)
    )
);

create table change_requests (
    change_request_id bigserial primary key,
    document_id bigint not null references documents(document_id) on delete cascade,
    request_no varchar(100) not null unique,
    title varchar(200) not null,
    description text,
    status varchar(30) not null default 'OPEN',
    requested_by bigint references users(user_id),
    requested_at timestamptz not null default now()
);

create table approvals (
    approval_id bigserial primary key,
    change_request_id bigint not null references change_requests(change_request_id) on delete cascade,
    approver_user_id bigint not null references users(user_id),
    approval_status varchar(20) not null check (approval_status in ('PENDING','APPROVED','REJECTED')),
    comment text,
    decided_at timestamptz
);

create table audit_logs (
    audit_log_id bigserial primary key,
    object_type varchar(50) not null,
    object_id bigint not null,
    action varchar(50) not null,
    old_value jsonb,
    new_value jsonb,
    user_id bigint references users(user_id),
    created_at timestamptz not null default now()
);

create table integration_jobs (
    integration_job_id bigserial primary key,
    document_id bigint references documents(document_id) on delete cascade,
    bom_header_id bigint references bom_headers(bom_header_id) on delete cascade,
    target_system varchar(30) not null,
    job_type varchar(50) not null,
    status varchar(30) not null default 'PENDING',
    request_payload jsonb not null,
    response_payload jsonb,
    created_at timestamptz not null default now(),
    finished_at timestamptz
);
```

## 8. 실무상 중요한 포인트

- ezdxf는 DXF를 읽고 수정하고 저장하는 데 적합하며, JSON tags로의 변환도 지원합니다.[^6][^1]
- PostgreSQL은 CHECK로 값 검증, UNIQUE로 중복 방지, FOREIGN KEY로 참조 무결성을 강하게 보장할 수 있습니다.[^5][^2]
- 3D와 STEP/IGES는 OCCT XDE를 중심으로 설계하는 것이 맞고, 2D는 DXF 중심이 안정적입니다.[^3][^4]
