# 화면별 와이어프레임 상세 항목표 그리고, API Request와 Response JSON 스키마 작성하고, PostgreSQL 인덱스와 트리거 DDL 추가하고, MVP 개발을 위한 단위 테스트 시나리오 까지 만들어서 개발 시나리오에 맞게 정리해줘

아래는 **개발 시나리오 기준 최종 작업 패키지**입니다. 화면 와이어프레임, API 스키마, PostgreSQL 인덱스/트리거, 단위 테스트 시나리오를 서로 연결해서 바로 백로그로 옮길 수 있게 정리했습니다. PostgreSQL은 CREATE INDEX로 B-tree 등 다양한 인덱스를 만들 수 있고, 트리거는 INSERT/UPDATE/DELETE 전후에 자동 실행되도록 정의할 수 있습니다.[^1][^2]

## 3. PostgreSQL 인덱스 DDL

PostgreSQL의 CREATE INDEX는 성능 향상을 위해 사용되며, B-tree, hash, GiST, GIN, BRIN 등을 지원합니다.[^3][^1]

```sql
create index idx_projects_status on projects (status);
create index idx_projects_customer_name on projects (customer_name);

create index idx_documents_project_id on documents (project_id);
create index idx_documents_status on documents (status);
create unique index ux_documents_project_doc_no on documents (project_id, doc_no);

create index idx_document_revisions_document_id on document_revisions (document_id);
create unique index ux_document_revisions_doc_rev on document_revisions (document_id, revision_no);

create index idx_drawings_document_id on drawings (document_id);
create index idx_layers_drawing_id on layers (drawing_id);
create index idx_entities_revision_id on entities (revision_id);
create index idx_entities_layer_id on entities (layer_id);

create index idx_dimensions_drawing_id on dimensions (drawing_id);
create index idx_constraints_drawing_id on constraints (drawing_id);

create unique index ux_parts_part_no on parts (part_no);
create unique index ux_assemblies_assembly_no on assemblies (assembly_no);

create index idx_bom_headers_document_id on bom_headers (document_id);
create index idx_bom_items_bom_header_id on bom_items (bom_header_id);
create index idx_bom_items_part_id on bom_items (part_id);
create index idx_bom_items_assembly_id on bom_items (assembly_id);

create index idx_change_requests_document_id on change_requests (document_id);
create index idx_change_requests_status on change_requests (status);

create index idx_approvals_change_request_id on approvals (change_request_id);
create index idx_audit_logs_object_lookup on audit_logs (object_type, object_id, created_at desc);

create index idx_integration_jobs_status on integration_jobs (status);
create index idx_integration_jobs_target_system on integration_jobs (target_system);
```


## 4. 트리거 DDL

PostgreSQL 트리거는 INSERT, UPDATE, DELETE 전후에 per-row 또는 per-statement로 실행되며, 먼저 trigger function을 만든 뒤 CREATE TRIGGER를 정의합니다.[^2][^4]

### 4.1 감사로그 트리거 함수

```sql
create or replace function fn_audit_log()
returns trigger
language plpgsql
as $$
begin
    insert into audit_logs (
        object_type,
        object_id,
        action,
        old_value,
        new_value,
        user_id,
        created_at
    )
    values (
        tg_table_name,
        coalesce((new.id)::bigint, (old.id)::bigint),
        tg_op,
        to_jsonb(old),
        to_jsonb(new),
        null,
        now()
    );

    return coalesce(new, old);
end;
$$;
```


### 4.2 감사로그 트리거

```sql
create trigger trg_documents_audit
after insert or update or delete on documents
for each row execute function fn_audit_log();

create trigger trg_document_revisions_audit
after insert or update or delete on document_revisions
for each row execute function fn_audit_log();

create trigger trg_bom_items_audit
after insert or update or delete on bom_items
for each row execute function fn_audit_log();
```


### 4.3 개정 변경 시 current_revision 자동 갱신

```sql
create or replace function fn_set_current_revision()
returns trigger
language plpgsql
as $$
begin
    update documents
       set current_revision_id = new.revision_id,
           status = case when status = 'DRAFT' then 'IN_REVIEW' else status end
     where document_id = new.document_id;

    return new;
end;
$$;

create trigger trg_set_current_revision
after insert on document_revisions
for each row execute function fn_set_current_revision();
```


### 4.4 BOM 품질 검증 트리거

```sql
create or replace function fn_validate_bom_item()
returns trigger
language plpgsql
as $$
begin
    if new.qty <= 0 then
        raise exception 'qty must be greater than zero';
    end if;

    if new.part_id is null and new.assembly_id is null then
        raise exception 'either part_id or assembly_id must be set';
    end if;

    return new;
end;
$$;

create trigger trg_validate_bom_item
before insert or update on bom_items
for each row execute function fn_validate_bom_item();
```


## 5. MVP 단위 테스트 시나리오

ezdxf는 DXF 문서 관리와 파싱/저장 흐름을 갖고 있으므로, 테스트는 파일 입출력과 렌더링 데이터 검증을 분리하는 방식이 적합합니다.[^5][^6]

### 5.1 인증 테스트

- 정상 로그인 시 토큰 발급 확인.
- 비밀번호 오류 시 실패 응답 확인.
- 비활성 계정 차단 확인.
- OTP 누락 시 거절 확인.


### 5.2 프로젝트 테스트

- 프로젝트 코드 중복 시 실패.
- 필수 필드 누락 시 실패.
- 정상 생성 후 목록 조회 확인.


### 5.3 DXF 업로드 테스트

- 유효한 DXF 파일 업로드 성공.
- 손상된 DXF 파일 실패.
- 지원하지 않는 버전 파일 경고 처리.
- 레이어/엔티티 개수 일치 확인.


### 5.4 뷰어 테스트

- 줌 인/아웃 좌표 유지 확인.
- 팬 후 중심점 갱신 확인.
- 레이어 숨김 시 미표시 확인.
- 객체 선택 시 속성 패널 갱신 확인.


### 5.5 스냅 테스트

- Endpoint 반경 내 좌표 보정 확인.
- Midpoint 우선순위 규칙 확인.
- 스냅 대상 없을 때 원 좌표 유지 확인.
- 여러 후보 시 가장 가까운 점 선택 확인.


### 5.6 편집 테스트

- 선 생성 후 객체 수 증가 확인.
- 이동 후 좌표 변화 확인.
- Undo 후 원상복구 확인.
- 삭제 후 DB 반영 확인.


### 5.7 Revision 테스트

- 새 Revision 생성 시 current_revision 갱신 확인.
- 승인 전 상태에서 외부 export 차단 확인.
- 비교 기능에서 diff 수치 확인.


### 5.8 BOM 테스트

- 도면 속성에서 BOM 생성 확인.
- 수량 음수 입력 시 실패 확인.
- part_id/assembly_id 둘 다 null이면 실패 확인.
- ERP 전송 payload 생성 확인.


### 5.9 트리거 테스트

- documents 변경 시 audit_logs 생성 확인.
- document_revisions insert 시 documents.current_revision_id 갱신 확인.
- bom_items invalid row insert 시 exception 확인.


### 5.10 3D PoC 테스트

- 폐곡선 스케치만 Extrude 허용 확인.
- 열린 와이어는 실패 확인.
- Boolean 연산 성공 여부 확인.
- STEP export 파일 생성 확인.
