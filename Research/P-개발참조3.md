# OpenAPI 3.0 YAML 초안 작성하고, pytest 단위 테스트 코드 작성하고, CI/CD 파이프라인 구성안 작성하고, 도커 및 쿠버네티스 배포 구성안 작성하고, 보안 및 권한 관리 설계서 작성해, 개발 순서 및 시나리오에 맞게 재구성 및 정리해줘

아래는 **개발 시나리오 순서에 맞춘 실행 패키지**입니다. OpenAPI 3.0 YAML 초안, pytest 단위 테스트 코드, CI/CD, 도커·쿠버네티스 배포, 보안·권한 설계를 한 흐름으로 묶었습니다. pytest는 fixtures, parametrization, temporary directory, raises 등을 지원해 CAD 파일 처리 테스트에 적합하고, Kubernetes는 컨테이너화된 앱 배포·스케일링·관리를 위한 표준 오케스트레이션입니다.[^1][^2]

## 1. 개발 순서

### Phase 1. 계약 우선

- API 명세 확정.
- OpenAPI YAML 초안 작성.
- 인증/프로젝트/도면/DXF/BOM 핵심 엔드포인트부터 정의.
- 응답 표준은 `success`, `data`, `error` 공통 포맷으로 통일.


### Phase 2. 테스트 우선

- pytest로 API 단위 테스트 작성.
- DXF 샘플 파일과 tmp_path 기반 파일 테스트 구성.
- DB 트랜잭션 롤백형 테스트 설계.


### Phase 3. 배포 우선

- Dockerfile, docker-compose, Kubernetes manifests 설계.
- CI/CD에서 lint → test → build → push → deploy 순으로 자동화.
- 보안은 인증, RBAC, 비밀관리, 감사로그를 함께 넣음.


### Phase 4. 운영 확장

- 3D/OCCT 연동 추가.
- 성능 측정, 스케일링, 캐시 최적화.
- 승인 워크플로와 외부 ERP 연계 고도화.


## 2. OpenAPI 3.0 YAML 초안

아래는 **핵심 API만 포함한 초안**입니다.

```yaml
openapi: 3.0.3
info:
  title: In-house CAD API
  version: 0.1.0
  description: CAD document, drawing, DXF import, BOM, approval API
servers:
  - url: https://cad-api.company.local
tags:
  - name: auth
  - name: projects
  - name: documents
  - name: drawings
  - name: files
  - name: bom
  - name: workflow

paths:
  /api/auth/login:
    post:
      tags: [auth]
      summary: Login
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/LoginRequest'
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/LoginResponse'

  /api/projects:
    get:
      tags: [projects]
      summary: List projects
      responses:
        '200':
          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ProjectListResponse'
    post:
      tags: [projects]
      summary: Create project
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/ProjectCreateRequest'
      responses:
        '201':
          description: Created
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/ProjectResponse'

      tags: [documents]

      responses:
        '200':

              schema:
                $ref: '#/components/schemas/DocumentListResponse'

      summary: Create document
      requestBody:

            schema:
              $ref: '#/components/schemas/DocumentCreateRequest'
      responses:
        '201':
          description: Created
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/DocumentResponse'

  /api/files/dxf/import:
    post:
      tags: [files]
      summary: Import DXF
      requestBody:

              $ref: '#/components/schemas/DxfImportRequest'

    post:

          description: OK
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BomPreviewResponse'

components:
  schemas:

      type: object
      properties:
        code: { type: string }
        message: { type: string }
        details: { type: object, additionalProperties: true }

    CommonResponse:
      type: object
      properties:
        success: { type: boolean }
        data: { nullable: true }
        error:
          oneOf:
            - $ref: '#/components/schemas/ApiError'
            - type: 'null'

    LoginRequest:
      type: object
      required: [login_id, password]
      properties:
        login_id: { type: string }
        password: { type: string, format: password }
        otp_code: { type: string }
        remember_me: { type: boolean, default: false }

    LoginResponse:
      allOf:
        - $ref: '#/components/schemas/CommonResponse'
        - type: object
          properties:
            data:
              type: object
              properties:
                access_token: { type: string }
                refresh_token: { type: string }
                user:
                  type: object
                  properties:
                    user_id: { type: integer }
                    login_id: { type: string }
                    user_name: { type: string }

                      type: array
                      items: { type: string }

    ProjectCreateRequest:

          properties:

              type: object

                project_id: { type: integer }

                project_name: { type: string }
                status: { type: string }

    DocumentCreateRequest:
      type: object
      required: [project_id, doc_no, doc_type, title]

        doc_type:
          type: string

        title: { type: string }

    DxfImportRequest:
      type: object
      required: [project_id, document_id, file_name, file_content_base64]
```

## 3. pytest 단위 테스트 코드

pytest는 `assert`, `raises`, fixtures, `tmp_path`, parametrization을 지원하므로 파일 기반 CAD 검증에 잘 맞습니다.[^3][^4][^1]

```python
# tests/test_api_contract.py
import pytest

def test_login_response_shape():
    resp = {
        "success": True,
        "data": {
            "access_token": "jwt",
            "refresh_token": "rjwt",
            "user": {"user_id": 1, "login_id": "kim01", "user_name": "김철수", "roles": ["DESIGNER"]}
        },
        "error": None
    }
    assert resp["success"] is True
    assert "access_token" in resp["data"]
    assert isinstance(resp["data"]["user"]["roles"], list)

@pytest.mark.parametrize(
    "qty,expected",
    [(1, True), (0, False), (-1, False)]
)
def test_bom_qty_rule(qty, expected):
    ok = qty > 0
    assert ok is expected

def test_dxf_import_raises_on_bad_file(tmp_path):
    bad_file = tmp_path / "bad.dxf"
    bad_file.write_text("not a dxf")
    with pytest.raises(Exception):
        raise Exception("DXF parse failed")

def test_revision_current_update():
    document = {"current_revision_id": None, "status": "DRAFT"}
    new_revision_id = 9001
    document["current_revision_id"] = new_revision_id
    if document["status"] == "DRAFT":
        document["status"] = "IN_REVIEW"
    assert document["current_revision_id"] == 9001
    assert document["status"] == "IN_REVIEW"

def test_snap_pick_endpoint():
    candidates = [
        {"type": "MIDPOINT", "dist": 12.0},
        {"type": "ENDPOINT", "dist": 3.0},
    ]
    best = sorted(candidates, key=lambda x: x["dist"])[^0]
    assert best["type"] == "ENDPOINT"
```

## 4. CI/CD 파이프라인 구성안

### 파이프라인 단계

1. **Lint**
    - ruff, black, mypy
2. **Unit Test**
    - pytest
3. **Package**
    - wheel 또는 Docker image 생성
4. **Security Scan**
    - dependency scan, secret scan
5. **Push**
    - registry push
6. **Deploy**
    - dev → staging → production 순차 승격

### GitHub Actions 예시

```yaml
name: cad-ci

on:
  push:
    branches: [main, develop]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - run: pip install -U pip pytest ruff black
      - run: ruff check .
      - run: black --check .
      - run: pytest -q

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: docker build -t registry.local/cad-api:${{ github.sha }} .

  deploy-dev:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/develop'
    steps:
      - run: echo "deploy to dev cluster"
```

pytest는 실패 시 상세한 assertion introspection과 fixture 기반 분리가 강점이며, Kubernetes는 컨테이너 관리 표준이라 배포 자동화와 궁합이 좋습니다.[^2][^1]

## 5. 도커 및 쿠버네티스 배포 구성안

### Dockerfile 예시

```dockerfile
FROM python:3.11-slim

WORKDIR /app

ENV PYTHONDONTWRITEBYTECODE=1
ENV PYTHONUNBUFFERED=1

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```


### docker-compose 예시

```yaml
version: "3.9"
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      DATABASE_URL: postgresql://cad:cad@db:5432/cad
    depends_on:
      - db
  db:
    image: postgres:16
    environment:
      POSTGRES_DB: cad
      POSTGRES_USER: cad
      POSTGRES_PASSWORD: cad
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```


### Kubernetes 배포 구성

- **Deployment**: API, worker, viewer service
- **Service**: ClusterIP/LoadBalancer
- **Ingress**: 외부 진입점
- **ConfigMap**: 일반 설정
- **Secret**: DB 비밀번호, JWT secret
- **HPA**: API autoscaling
- **PV/PVC**: 파일 저장소
- **Job/CronJob**: 변환 작업, 배치 export


### k8s Deployment 예시

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cad-api
spec:
  replicas: 2
  selector:
    matchLabels:
      app: cad-api
  template:
    metadata:
      labels:
        app: cad-api
    spec:
      containers:
        - name: api
          image: registry.local/cad-api:latest
          ports:
            - containerPort: 8000
          envFrom:
            - configMapRef:
                name: cad-config
            - secretRef:
                name: cad-secret
```


## 6. 보안 및 권한 관리 설계

### 인증

- 사내 SSO 또는 LDAP 연동.
- API는 JWT access/refresh 토큰 사용.
- 민감 작업은 MFA 추가.


### 권한

- **ADMIN**: 시스템 설정, 권한 부여
- **DESIGNER**: 도면 작성/편집
- **REVIEWER**: 검토/승인
- **MANUFACTURING**: BOM 조회, 배포 확인
- **VIEWER**: 열람 전용


### 원칙

- 최소권한.
- 프로젝트 단위 접근통제.
- 승인 전 외부 export 제한.
- 감사로그 의무화.
- 비밀정보는 Secret로 관리.


### API 보안

- 입력 검증.
- 파일 크기 제한.
- DXF/DWG 악성 파일 검사.
- rate limiting.
- CORS 제한.
- 이중 인증 작업 분리.
