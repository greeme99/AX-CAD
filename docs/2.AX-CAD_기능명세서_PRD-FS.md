## 2. 기능 상세 명세

### 공통 규칙 (모든 FN에 적용)

- API 응답은 `{ "success": bool, "data": any|null, "error": {code, message, details}|null }` 형식으로 통일한다.
- 내부 길이 단위는 **mm**, 각도는 API에서 **deg**로 주고받고 커널 내부에서 rad로 변환한다.
- 금액·단가는 `Decimal`(DB `numeric(18,2)`), 수량은 `numeric(18,6)`.
- 모든 변경 API는 감사 로그(FN-26) 대상이다.
- 오류 코드는 `도메인_원인` 형식(예: `DXF_INVALID_HEADER`, `GEOM_OPEN_WIRE`, `QUOTE_PRICE_MISSING`).

---

### [FN-01] DXF 업로드·파싱

- **설명**: 사용자가 올린 DXF를 검증·파싱하여 도면 Revision과 엔티티로 저장한다.
- **입력**: `multipart/form-data` — `file`(.dxf), `document_id`, `revision_note`(선택)
- **처리 로직**:
  1. 확장자 `.dxf` 확인 → 크기 ≤ 50MB 확인(설정값)
  2. 헤더 확인: Binary DXF 시그니처(`AutoCAD Binary DXF\r\n\x1a\x00`) 또는 ASCII 텍스트(앞쪽 `999` 주석·공백 허용 후 첫 그룹이 `0`/`SECTION`), NUL 바이트 포함 텍스트 거부
  3. 격리된 임시경로 저장(원본 파일명 사용 금지, UUID 파일명)
  4. `ezdxf.readfile()` 파싱(타임아웃 30초, 별도 워커 프로세스)
  5. `modelspace`, `paperspace` 레이아웃, `blocks` 구분 추출
  6. 엔티티별 `handle`, `type`, `layer`, 기하(JSON), 레이어 테이블 저장
  7. 파일 SHA-256 해시 계산 → Revision 생성(FN-09)
- **출력**: `{revision_id, entity_count, layer_count, block_count, warnings[]}`
- **업무 규칙**:
  - 지원 엔티티: LINE, CIRCLE, ARC, LWPOLYLINE, POLYLINE, TEXT, MTEXT, INSERT, DIMENSION, HATCH. 그 외는 저장하되 `warnings`에 표기.
  - 견적 메트릭 계산은 Modelspace 기준(Paperspace는 표제란 텍스트 추출용).
  - 도면 단위(`$INSUNITS`)가 mm가 아니면 mm로 환산하고 warning 기록. 단위 미지정은 mm로 가정하고 warning.
- **예외 처리**:
  - 확장자/매직 불일치 → 400 `DXF_INVALID_FILE`
  - 크기 초과 → 413 `FILE_TOO_LARGE`
  - 파싱 실패(손상) → 422 `DXF_PARSE_ERROR` (ezdxf 오류 메시지 요약 포함)
  - XREF 포함 → 외부 참조는 로드하지 않고 warning `DXF_XREF_IGNORED`
  - 블록 중첩 깊이 > 16 또는 전개 엔티티 > 500,000 → 422 `DXF_BLOCK_LIMIT`
  - 타임아웃 → 504 `DXF_PARSE_TIMEOUT`
- **데이터 요구사항**:
  - 저장: `document_revisions`(file_path, checksum, file_format='DXF'), `layers`, `entities`(entity_handle, entity_type, layer_id, space, block_name, geometry_json, attr_json)
- **권한**: DESIGNER, ADMIN
- **완료 기준**: 샘플 DXF 15종의 엔티티·레이어 수가 기대값과 일치, 악성/손상 샘플 전부 거부.

### [FN-02] 2D 뷰어

- **설명**: Revision의 엔티티를 Canvas2D에 렌더링하고 탐색한다.
- **입력**: `GET /api/revisions/{revision_id}/render` 결과, 마우스 휠/드래그, 레이어 토글
- **처리 로직**:
  1. 렌더 데이터(엔티티 기하 + 레이어 색/선종) 로드
  2. 월드(mm) ↔ 화면(px) 변환 행렬 유지
  3. 휠: 커서 위치 고정 줌(배율 1.2), 중클릭/스페이스+드래그: 팬
  4. 레이어 토글 시 해당 레이어 엔티티 숨김
  5. 클릭: 화면 허용오차(5px) 내 최근접 엔티티 선택 → 속성 패널 표시
- **출력**: 캔버스, 상태바(커서 X/Y mm, 배율, 활성 레이어)
- **업무 규칙**: 뷰어는 기하를 계산하지 않는다(서버가 준 기하만 그림). 선택 판정용 거리 계산만 클라이언트 유틸 사용.
- **예외 처리**: 엔티티 0개 → "빈 도면" 안내. 미지원 엔티티 → 회색 점선 BBox로 표시.
- **권한**: 전 역할(조회)
- **완료 기준**: 줌 전후 커서 아래 월드 좌표 차이 < 1e-6mm, 레이어 숨김 시 미표시.

### [FN-03] 2D 작도 도구

- **설명**: 선·원·호·폴리라인·텍스트를 마우스/명령창으로 작도한다.
- **입력**: 도구 선택(툴바/단축키 `L`,`C`,`A`,`PL`,`T`), 클릭 좌표(스냅 적용), 명령창 수치 입력
- **처리 로직 (상태머신)**: `IDLE → TOOL_ACTIVE → PICK_1 → PICK_n → COMMIT | CANCEL(Esc)`
  - 선: 시작점 → 끝점 (연속 작도, Enter로 종료)
  - 원: 중심 → 반지름(점 또는 수치)
  - 호: 3점 또는 중심-시작-끝
  - 폴리라인: 점 연속 → `C`로 닫기
  - 텍스트: 삽입점 → 높이 → 내용
- **출력**: 미리보기(러버밴드) → 확정 시 엔티티 추가, 명령 이력 기록
- **업무 규칙**: 확정 시 활성 레이어에 생성. 길이 0 선, 반지름 ≤ 0 원은 생성 불가.
- **예외 처리**: 퇴화 형상 → 명령창 오류 "길이가 0인 선은 만들 수 없습니다". Esc → 현재 명령 취소, 이미 확정된 세그먼트는 유지.
- **권한**: DESIGNER
- **완료 기준**: 상태머신 전이 테스트 전 경로 통과, 퇴화 입력 거부.

### [FN-04] 편집·Undo/Redo

- **입력**: 선택 집합 + 명령(이동 `M`, 복사 `CO`, 삭제 `Del`, 속성 수정)
- **처리 로직**: 모든 변경을 Command 객체(do/undo)로 실행하고 이력 스택에 push. `Ctrl+Z`/`Ctrl+Y`.
- **업무 규칙**: 이력 최대 200단계. 저장(FN-07) 후에도 세션 내 Undo 가능. 잠긴 레이어 객체는 편집 불가.
- **예외 처리**: 빈 선택에서 편집 명령 → "객체를 먼저 선택하세요".
- **권한**: DESIGNER
- **완료 기준**: N회 편집 후 N회 Undo 시 초기 상태와 엔티티 기하가 동일.

### [FN-05] 스냅 엔진

- **설명**: 커서 근처의 기하 특징점으로 좌표를 보정한다.
- **입력**: 커서 월드 좌표, 활성 스냅 종류, 스냅 반경(px, 기본 12)
- **처리 로직**:
  1. 엔티티 로드/변경 시 특징점(끝점, 중점, 원·호 중심)을 **그리드 버킷 인덱스**에 등록
  2. 커서 이동 시 반경(px→mm 환산) 내 버킷만 조회
  3. 후보 중 거리 최소 점 선택. 동일 거리 시 우선순위 Endpoint > Center > Midpoint > Grid
  4. 스냅 마커 표시(DESIGN.md 마커 규격), 상태바에 스냅 종류 표기
- **출력**: 보정 좌표 `{x, y, snap_type, entity_handle}` 또는 원좌표
- **업무 규칙**: 전체 엔티티 순회 금지(`.claude/rules/cad-geometry.md`). `F3`로 스냅 전체 on/off.
- **예외 처리**: 후보 없음 → 원좌표 유지, 마커 없음.
- **권한**: DESIGNER
- **완료 기준**: 1만 엔티티에서 질의 < 5ms, 최근접 선택·우선순위 테스트 통과.

### [FN-06] 치수 기입

- **입력**: 치수 종류(선형/정렬/각도/반지름), 측정점 2~3개, 치수선 위치
- **처리 로직**: 측정값 계산 → ezdxf DIMENSION 엔티티 생성(치수 스타일 적용) → 렌더링
- **업무 규칙**: 표시 소수점 2자리(mm), 치수 스타일은 기준정보(사내 표준)에서 로드. 치수는 견적 계산에 사용하지 않음(검증 참고용).
- **예외 처리**: 측정점이 동일 → 생성 불가.
- **권한**: DESIGNER
- **완료 기준**: 저장 후 DXF 재로드 시 치수값 일치.

### [FN-07] DXF 저장·내보내기

- **입력**: 현재 편집 상태, 저장 메모
- **처리 로직**: 엔티티 목록 → ezdxf 문서 생성(원본 헤더·레이어·블록 보존) → 저장 → 새 Revision(FN-09)
- **업무 규칙**: 원본에서 수정하지 않은 엔티티의 handle 유지(추적성). 내보내기 버전 기본 R2018.
- **예외 처리**: 미승인 도면의 "외부 배포용 내보내기"는 FN-22 규칙에 따라 차단(사내 저장은 허용).
- **권한**: DESIGNER (저장), 승인된 도면 내보내기는 DESIGNER·MANUFACTURING
- **완료 기준**: 작도→저장→재로드 좌표 오차 ≤ 1e-6, 미수정 엔티티 handle 불변.

### [FN-08] 프로젝트·도면 관리

- **입력**: 프로젝트(코드, 이름, 고객사), 문서(doc_no, doc_type: DRAWING/PART/ASSEMBLY, title)
- **처리 로직**: CRUD, 검색(코드/이름/상태), 아카이브(삭제 대신 상태 변경)
- **업무 규칙**: `project_code` 전역 유일, `(project_id, doc_no)` 유일. 물리 삭제 금지(아카이브).
- **예외 처리**: 중복 → 409 `DUPLICATE_KEY`, 필수값 누락 → 422.
- **권한**: 생성/수정 DESIGNER·ADMIN, 조회 전 역할(프로젝트 멤버)
- **완료 기준**: 중복·필수값 검증 테스트 통과.
- **구현 결정 (Track 2)**: 요청 검증 오류는 전 API 공통 422 `REQUEST_INVALID`, `details = [{field, type}]`(예: `project_code`/`missing`). 제출값·Pydantic 메시지는 응답에 싣지 않는다(입력 반사 방지). 편집 요청(`/edits`)은 기존대로 422 `EDIT_INVALID`, 잘못된 Content-Length는 400.

### [FN-09] Revision 관리

- **처리 로직**: Revision 생성 시 번호 자동 증가(A, B, C…), `documents.current_revision_id` 갱신, 상태 DRAFT→IN_REVIEW 전환 규칙 적용
- **업무 규칙**: Revision은 불변(immutable). 수정은 항상 새 Revision. 비교 기능은 엔티티 수·레이어별 추가/삭제/변경 개수 요약.
- **예외 처리**: 동일 체크섬 파일 재업로드 → warning "변경 없음", Revision 생성 안 함.
- **권한**: DESIGNER(생성), 전 역할(조회)
- **완료 기준**: 트리거/서비스 테스트로 current_revision 갱신 확인.

### [FN-10] 스케치 → Extrude/Revolve

- **설명**: 2D 폐곡선을 3D 솔리드로 변환한다.
- **입력**: 선택한 2D 엔티티 handle 목록, 작업평면, `Extrude{distance, direction}` 또는 `Revolve{axis_point, axis_dir, angle_deg}`
- **처리 로직**:
  1. 엔티티 → OCCT Edge 변환(mm)
  2. Wire 구성 → **사전검증**: 닫힘(`IsClosed`), 자가교차, 퇴화 모서리(길이 < 1e-6)
  3. Face 생성 → `BRepPrimAPI_MakePrism` / `BRepPrimAPI_MakeRevol`
  4. `BRepCheck_Analyzer`로 결과 검증
  5. Feature(파라미터 JSON) 저장, 결과 BREP 캐시 저장, 테셀레이션 메시 반환
- **출력**: `{feature_id, shape_id, volume, surface_area, bbox, mesh_url}`
- **업무 규칙**: 형상의 진실 원천은 **Feature 파라미터**(재생성 가능), BREP은 캐시.
- **예외 처리**: 열린 와이어 → 422 `GEOM_OPEN_WIRE`(열린 끝점 좌표 반환), 자가교차 → `GEOM_SELF_INTERSECTION`, 거리/각도 ≤ 0 → `GEOM_INVALID_PARAM`, 결과 무효 → `GEOM_INVALID_RESULT`
- **권한**: DESIGNER
- **완료 기준**: 사각형 Extrude 부피 = w·h·d, 원 Revolve(원통) 부피 = πr²h, 상대오차 ≤ 1e-6.

### [FN-11] Boolean 연산

- **입력**: `{operation: FUSE|CUT|COMMON, target_shape_id, tool_shape_id}`
- **처리 로직**: 입력 형상 검증 → `BRepAlgoAPI_*` 실행 → 실패 시 `ShapeFix_Shape` 후 1회 재시도 → 결과 검증 → Feature 기록
- **예외 처리**: 결과 빈 형상(COMMON 무교차) → 422 `GEOM_EMPTY_RESULT`. 커널 예외는 500이 아닌 422 `GEOM_BOOLEAN_FAILED`로 감싸 반환(서버 프로세스 크래시 방지 위해 워커 격리).
- **권한**: DESIGNER
- **완료 기준**: Cut 후 부피 = 원본 − 교차부피, 접촉면 일치 케이스에서 크래시 없음.

### [FN-12] STEP/IGES 입출력

- **입력**: import — 파일(.step/.stp/.iges/.igs, ≤ 100MB), export — `shape_id|document_id`, 포맷
- **처리 로직**: OCCT XDE(`STEPCAFControl_Reader/Writer`, `IGESCAFControl_*`)로 이름·조립 구조·색 보존 → Part/Assembly 트리 저장 → 파트별 계측(FN-15)

- **예외 처리**: 판독 실패 → 422 `STEP_READ_FAILED`, 빈 형상 → `STEP_EMPTY`, 타임아웃 120초 → 504 `STEP_TIMEOUT`. 확장자·매직 바이트 불일치 또는 외부 파일 참조(STEP `DOCUMENT_FILE`/`EXTERNAL_SOURCE`, IGES 416) → 422 `STEP_INVALID_FILE`. 솔리드 없는 곡면 모델은 Sewing 후 경고 `SEWN`(닫히지 않으면 `OPEN_SHELLS`).

- **완료 기준**: export→import 시 부피·면적 보존(≤ 1e-6), 샘플 STEP 5종 파트 수·조립 구조 일치.

### [FN-14] 2D 견적 메트릭 추출

- **설명**: DXF Revision에서 견적용 수치를 계산한다.
- **입력**: `revision_id`, 레이어 매핑 규칙(기준정보: 외곽선/절곡선/무시 레이어)
- **처리 로직**:
  1. INSERT를 `virtual_entities()`로 전개(중첩 포함), 반복 수 = INSERT 개수 × 배열 수
  2. **절단길이** = 외곽/내곽 윤곽 LINE·ARC·LWPOLYLINE(bulge 포함)·CIRCLE 둘레 합
  3. **구멍** = CIRCLE 개수·직경별 집계(직경 ≤ 설정값은 펀칭, 초과는 레이저 윤곽)
  4. **절곡** = 절곡선 레이어(또는 선종) LINE 개수·길이
  5. **면적** = 최외곽 폐곡선 면적 − 내부 구멍 면적, BBox
  6. **표제란** = Paperspace/Modelspace의 TEXT·MTEXT·ATTRIB에서 품번·품명·재질·두께·수량 추출(키워드/블록 속성 태그 규칙)
  7. 엔티티별 메트릭을 `source_entity.metrics_json`에 저장
- **출력**: `{cutting_length_mm, hole_count, holes_by_dia{}, bend_count, bend_length_mm, net_area_mm2, bbox, title_block{part_no, part_name, material, thickness_mm, qty}, warnings[]}`
- **업무 규칙**: TEXT·DIMENSION은 비용에 직접 반영하지 않음. 중복 선(동일 좌표 겹침, 허용오차 1e-6)은 1회만 계산하고 warning.
- **예외 처리**: 최외곽 폐곡선 없음 → `METRIC_NO_OUTER_CONTOUR` warning(면적·중량 미산출), 재질/두께 미추출 → 사용자 입력 요청 상태.
- **권한**: ESTIMATOR, DESIGNER
- **완료 기준**: 샘플 15종 기대 메트릭 표와 100% 일치(길이 허용오차 0.01mm).

### [FN-16] 기준정보 관리

- **입력/저장 대상**:
  - 재질: 코드(SS400, SUS304, AL6061 …), 비중(g/cm³), 단가(원/kg), 스크랩률
  - 공정 규칙: 공정코드, 입력 메트릭, 표준공수 공식, 기계시간당 경비
  - 임률: 공정/직무별 원/h
  - 원가 비율: 일반관리비율, 이윤율, VAT, 절사 규칙(원 단위 절사/반올림)
  - 레이어 매핑 규칙(FN-14)
- **처리 로직**: 모든 기준정보는 **버전(effective_from)**으로 관리. 수정 = 새 버전 생성. 값 입력은 G1 엑셀 양식 업로드로 초안 버전 전체를 교체(ADMIN, ≤ 5MB, 격리 파싱, 시트·행 단위 오류 보고)하고, 확인 후 활성화(확정)한다. 확정 버전은 DB 트리거로 동결.
- **업무 규칙**: 확정 견적은 생성 당시 버전을 참조(재현성, NFR-05). 비율은 0~100% CHECK.
- **권한**: ADMIN(수정), ESTIMATOR(조회)
- **완료 기준**: 버전 변경 후에도 기존 견적 재계산 결과 불변.

### [FN-17] 견적 자동 산출

- **설명**: 메트릭 + 기준정보로 한국표준 원가 체계 견적을 만든다.
- **입력**: `{quote_request_id, source_revision_ids[], qty(로트수량), material_code?, process_codes[]?, rule_set_version?, price_version?}`
- **처리 로직**:
  1. 메트릭(FN-14/15) 로드
  2. 규칙 YAML에서 메트릭 → 공정 매핑(예: cutting_length → LASER_CUT, bend_count → PRESS_BEND, hole_count → PUNCH)
  3. **직접재료비** = 정미중량(면적×두께×비중 또는 부피×비중) × 재질단가 × (1+스크랩률)
  4. **직접노무비** = Σ 공정 표준공수(공식: 예 `cutting_length_mm / cut_speed_mm_per_min / 60 + setup_h`) × 임률
  5. **제조간접비** = Σ 기계시간 × 기계시간당 경비
  6. 순제조원가 → 일반관리비 → 이윤 → 공급가액 → VAT → 최종금액
  7. 라인마다 `quote_trace`(source_entity/part → rule_code → price_item·version → 계산식·입력값) 저장
  8. 금액은 `Decimal`, 라인 금액은 원 단위 처리 규칙 적용 후 합산
- **출력**: 견적 헤더·라인·요약(재료비/노무비/경비/일반관리비/이윤/공급가액/세액/합계)·trace·warnings
- **업무 규칙**: 수량 0 라인은 생성하지 않고 warning. 규칙에 없는 메트릭은 무시하지 않고 warning `RULE_NOT_MAPPED`. 자동값은 `calculated_*` 컬럼에만 기록.
- **예외 처리**: 단가 없음 → 라인 생성 + validation ERROR `QUOTE_PRICE_MISSING`(합계에서 제외, 확정 불가). 재질 미지정 → `QUOTE_MATERIAL_REQUIRED`.
- **권한**: ESTIMATOR
- **완료 기준**: 수기 검증 견적 3건과 원 단위 일치, 모든 라인 trace 보유.
- **구현 결정 (S9)**: 규칙 YAML 대신 버전 관리되는 기준정보(FN-16)의 공정 규칙을 사용. 공식은 표준공수(분/개)이며 허용 연산만 해석(ast 화이트리스트, Decimal). 노무·기계 단가가 없는 공정은 공식 결과를 원/개로 보고 외주가공비로 계상. 제조간접비 배부(기계시간/노무비 비율)·절사 규칙·단위·시점(라인/합계)·재료 중량 기준(순면적/소재 사각)은 기준정보 값으로 선택. 견적은 그날 적용 중인 확정 버전을 FK로 고정하고 메트릭 스냅샷을 저장(재현성).

### [FN-19] 견적 수동 조정

- **입력**: `{quote_line_id, field(qty|unit_price|amount), override_value, override_reason(필수, ≥ 5자)}`
- **처리 로직**: `calculated_*` 유지 → `override_*`, `override_reason`, `overridden_by/at` 기록 → 요약 재계산(유효값 = override ?? calculated)
- **업무 규칙**: 승인된 견적은 조정 불가(새 견적 Revision 필요). UI는 조정 라인을 `MANUAL` 배지로 표시.
- **예외 처리**: 사유 누락 → 422, 음수 → 422.
- **권한**: ESTIMATOR
- **완료 기준**: 조정 후 `calculated_*` 불변(DB 테스트), 감사 로그 생성.
- **견적 Revision 구현 결정 (S11, 2026-10-10)**:
  - 개정은 확정(CONFIRMED)된 최신 견적에서만 만든다. 한 견적의 Revision은 하나뿐이다(분기 없는 체인, DB UNIQUE).
  - 번호는 `원번호-R{n}`, 개정 사유(5자 이상)는 필수다.
  - 방식 COPY: 확정 금액·수동 조정·trace·산출 로그를 그대로 복사한 초안. 조정 후 다시 승인받는다.
  - 방식 RECALC: 현재 도면 리비전(3D는 현재 모델)과 오늘의 기준정보로 재산출한다. 사용자가 입력했던 값만 승계하고 표제란 값은 새 도면에서 다시 읽는다.
  - 개정본이 승인되면 이전 견적은 SUPERSEDED가 된다. 이미 발행한 정식 견적서는 그대로 내려받을 수 있지만 새로 발행하지 않는다(409).
  - 재산출(연결 없는 새 견적)은 초안 견적에서만 제공한다.
  - 필요 없어진 초안 Revision은 폐기(ABANDONED)한다. 기록은 남고 번호는 재사용하지 않는다(R1 폐기 → 다음은 R2).
  - 승인자 제한의 "작성자"는 Revision 체인 전체의 작성자·조정자다(복사된 조정 포함).
  - 견적 헤더의 원천·금액·계보는 DB 트리거로 불변이고, 상태는 DRAFT↔IN_REVIEW→CONFIRMED→SUPERSEDED, DRAFT→ABANDONED로만 바뀐다.
  - 현재 활성 기준정보가 아닌 버전으로 산출된 견적은 검증에서 WARN(`QUOTE_MASTER_OUTDATED`).

  - 정식본은 형식(PDF/XLSX)별로 첫 발행 때 바이트·sha256·발행자를 `quote_reports`에 저장하고, 이후 다운로드는 저장본을 그대로 돌려준다(발행 후 설정·고객명이 바뀌어도 문서 불변). 견적일은 승인일. 초안은 등록하지 않는다.
  - 견적 본문은 품목 1행이다. 품명은 표제란 품명 또는 도면 제목, 규격은 품번·재질·두께, 단가는 공급가액÷수량이다. 금액은 수동 조정을 반영한 합계를 쓴다.
  - 공급받는자는 프로젝트의 고객명이다. 공급자와 유효기간·납기·결제조건·비고는 `backend/config/supplier.json`에서 읽는다. 현재 샘플 값이라 초안만 출력되고, 정식 출력은 409 `SUPPLIER_NOT_CONFIGURED`(샘플 표시 `_sample` 제거 + 사업자번호 형식 필요).
  - 산출근거 별첨(원가 내역·라인별 공식·수동 조정 사유)은 내부용이다. 초안에서만 선택(기본 해제)하며 "내부용·대외비"로 표시한다. 정식 견적서에는 붙일 수 없다(422).
  - 출력 권한은 ESTIMATOR·REVIEWER. MANUFACTURING은 견적 조회만 가능하고 문서 반출은 불가.

### [FN-22] 승인 워크플로

- **상태 전이**: `DRAFT → IN_REVIEW → APPROVED | REJECTED(→ DRAFT)`, `APPROVED → RELEASED`(도면)
- **처리 로직**: 승인 요청(검증 ERROR 0건 조건) → 승인자 지정 → 승인/반려(코멘트) → 상태 변경·감사 기록
- **업무 규칙**: 본인 작성 건 본인 승인 불가. 승인 전 외부 출력(FN-07 외부용, FN-21 정식, FN-24 전송) 차단.
- **권한**: 요청 DESIGNER·ESTIMATOR, 승인 REVIEWER
- **완료 기준**: 상태 전이 표 전 경로 테스트, 자기 승인 거부.
- **견적 구현 결정 (S11-a, 2026-10-10)**:
  - 견적 상태는 `DRAFT → IN_REVIEW → CONFIRMED`(승인 = 확정), 반려 시 `DRAFT`로 돌아가고 반려 기록은 `quote_approvals`에 남는다.
  - 요청 시 FN-20 검증을 다시 실행해 ERROR가 1건이라도 있으면 409 `QUOTE_HAS_ERRORS`.
  - "본인 작성 건"은 견적 작성자, 요청자, 라인을 한 번이라도 조정(또는 조정 취소)한 사람이다(감사 로그 기준). 모두 승인자가 될 수 없다.
  - 견적당 대기(PENDING) 요청은 1건만 존재한다(DB 부분 유일 인덱스).
  - 요청 의견(`comment`)과 결정 의견(`decision_comment`), 결정자(`decided_by`)를 따로 남긴다. 결정은 REVIEWER 역할 보유자만 한다(ADMIN 단독 불가).
  - 검토 중(`IN_REVIEW`)부터 라인 조정이 막힌다(API 409 `QUOTE_IN_REVIEW` + DB 트리거). 승인자가 보는 숫자가 바뀌지 않게 하기 위해서다.
  - 승인함의 견적 금액은 수동 조정을 반영한 합계다(승인 대상 금액). 승인함은 REVIEWER가 현재 구성원인 프로젝트의 건만 보여 준다.
  - 승인자가 퇴사 등으로 결정할 수 없으면 ADMIN이 요청을 취소(`CANCELLED`)해 `DRAFT`로 돌린다.
  - 승인 이력이 있으면 마이그레이션 0008 downgrade를 거부한다(감사 증적 보존).

### [FN-23] BOM 생성

- **입력**: 도면 Revision 또는 STEP 조립구조
- **처리 로직**: 블록 이름/속성(ATTRIB) 또는 STEP 파트명 → 품번 매핑(기준정보) → 수량 = 전개 인스턴스 수 → BOM 헤더/아이템 저장 → CSV/JSON export
- **업무 규칙**: 매핑 실패 품목은 "미매핑"으로 표시하고 수동 지정. 수량 > 0.
- **권한**: DESIGNER, MANUFACTURING
- **완료 기준**: BOM 수량 = INSERT 전개 수량(샘플 기대값).
- **구현 결정 (S12-a, 2026-10-10)**:
  - 도면 BOM은 현재 리비전의 modelspace INSERT를 블록 이름별로 집계한다. MINSERT는 행×열, 중첩 블록은 곱해서 센다(블록 정의별 1회 계산, 전개하지 않음). 익명 블록(`*`)·XREF는 제외.
  - 품번·품명은 인스턴스 ATTRIB(PART_NO/품번, PART_NAME/품명 등)에서 읽는다. 없으면 UNMAPPED로 두고 화면에서 직접 입력(MANUAL). 블록명→품번 기준정보 매핑은 G1 이후.
  - 3D BOM은 STEP/IGES 가져오기 부품(인스턴스 수)과 직접 만든 솔리드(1개)로 만든다. 품번은 모두 UNMAPPED에서 시작.
  - 추출된 수량·원천은 DB 트리거로 불변이고, 품번 매핑만 바꿀 수 있다(감사 로그).
  - 레벨은 1(도면에 직접 배치)과 2(다른 블록 안에만 있음)로만 구분한다. 다단 트리는 후속.
  - 품번 규칙(자동·수동 공통): 앞뒤 공백 제거 후 문자·숫자로 시작, 문자·숫자·`. - / _`·공백, 64자 이내. 도면 속성 값이 규칙에 어긋나면 UNMAPPED + 경고.
  - 수동 지정은 미매핑·수동 품목만 가능하다. 도면에서 읽은 품번(AUTO)은 도면을 고쳐 다시 생성한다. ERP로 보낸 BOM은 바꿀 수 없다.

### [FN-24] ERP 전송

- **처리 로직**: 승인된 BOM/견적 → ERP 어댑터 payload 변환 → `integration_jobs`(PENDING) → 전송 → SUCCESS/FAILED, 실패 시 지수 백오프 재시도(최대 3회)
- **업무 규칙**: 전송은 멱등 키(문서+Revision)로 중복 방지. ERP 자격증명은 환경변수/시크릿.
- **권한**: MANUFACTURING, ADMIN
- **완료 기준**: payload 스키마 테스트, 모의 ERP 서버로 실패·재시도 테스트.
- **구현 결정 (S12-b, 2026-10-10)**:
  - "승인된 BOM"은 원천 도면이 APPROVED/RELEASED이고, BOM이 그 현재 리비전에서 만들어졌으며, 미매핑 품목이 없는 경우다(BOM 별도 승인 절차는 두지 않음).
  - 멱등 키는 `BOM:{문서}:{리비전}`이다(3D는 리비전이 없어 생성 당시 모델 상태 해시 `MODEL:{해시}`, 모델이 바뀌면 BOM_OUTDATED). 같은 키를 다시 보내면 기존 작업을 돌려주고 ERP로 재전송하지 않는다. ERP에도 `Idempotency-Key` 헤더로 전달한다.
  - 전송은 요청 직후 서버 백그라운드에서 수행한다. 5xx·408·425·429·네트워크 오류는 지수 백오프로 최대 3회 시도하고, 그 밖의 4xx는 즉시 실패한다. 리다이렉트는 따라가지 않는다.
  - 연동 주소와 토큰은 환경변수(`ERP_API_URL`, `ERP_API_TOKEN`, `ERP_TIMEOUT_S` ≤ 30, `ERP_BACKOFF_S`)로만 설정한다. 주소는 https(개발용 localhost만 http). 토큰은 DB·응답·로그에 남기지 않고, ERP 응답에 섞여 오면 `***`로 바꾼다.
  - ERP 응답은 상태 코드와 2KB 텍스트만 저장하고, 본문은 ADMIN에게만 보인다.
  - 실패 작업과 10분 넘게 멈춘 작업은 연동 작업 화면(SCR-17)에서 재시도한다. 재시도는 같은 멱등 키로 보내며, 전송 때와 같은 승인·최신성 검사를 다시 한다. 재시도는 실행 ID를 새로 발급해 이전 워커가 상태를 덮어쓰지 못하게 한다.
  - payload 스키마 `ax-cad.bom.v1`: `idempotency_key, bom_no, project_code, document{doc_no,title,revision_no,source_type}, items[{item_no,part_no,part_name,qty,unit,level}]`.

### [FN-25] 인증·권한

- **처리 로직**: ID/비밀번호 로그인(argon2 해시) → access JWT(30분) + refresh(8시간) → 역할·프로젝트 멤버십으로 API 인가
- **업무 규칙**: 로그인 5회 실패 시 10분 잠금. 비활성 계정 차단.
- **권한**: 전원(로그인), ADMIN(사용자·역할 관리)
- **완료 기준**: 권한 매트릭스 테스트(역할×API) 통과.

### [FN-26] 감사 로그

- **처리 로직**: documents, document_revisions, quote_header, quote_line, 기준정보 테이블 변경 시 DB 트리거로 `audit_logs`(테이블, PK, 작업, old/new JSON, user_id, 시각) 기록. user_id는 세션 변수(`SET LOCAL app.user_id`)로 전달.
- **업무 규칙**: 감사 로그는 수정·삭제 불가(애플리케이션 계정에 UPDATE/DELETE 권한 없음).
- **구현 결정 (Track 3-4)**: 배포 시 API는 `axcad_app` 역할로 접속 — 전 테이블 SELECT/INSERT/UPDATE/DELETE, `audit_logs`는 UPDATE·DELETE·TRUNCATE 회수, 소유자가 아니므로 트리거 해제·DDL 불가. 역할·권한은 `python -m backend.cli app-role`이 마이그레이션 직후 매번 재부여(새 테이블 포함). 트리거(불변성) + 권한(우회 차단) 이중 보호.
- **권한**: ADMIN, REVIEWER(조회)
- **완료 기준**: 대상 테이블 변경 시 로그 생성 트리거 테스트 통과(Research D1 결함 수정 확인).
- **구현 결정 (Track 2)**:
  - 조회 범위: REVIEWER는 **자기가 구성원인 프로젝트**의 로그만 본다. 로그에 저장된 행 이미지의 `project_id` → `document_id` → `quote_id` → `bom_id` 순으로 프로젝트를 판정한다. 회사 공통 기준정보(`master_versions` 등 6개) 로그는 기준정보 API와 같은 범위(ESTIMATOR·ADMIN), 계정·역할·ERP 작업 로그는 ADMIN 전용. 멤버십은 조회 시점 기준(구성원에서 빠지면 그 프로젝트 이력도 안 보임).
  - 저장량: `fn_audit_log`의 두 번째 인자(쉼표 구분 컬럼 목록, 공백 없음)는 UPDATE 이미지에서 **값이 같을 때만** 뺀다. 변경 불가 컬럼에만 쓴다 — ERP 작업 `request_payload`(INSERT 이미지에는 남음, 마이그레이션 0014).

## 3. 사용자 흐름 (User Flow)

### 3.1 설계자: 도면 작성·개정

```text
로그인 → 프로젝트 선택 → 도면 목록 → [DXF 업로드 or 새 도면]
  → 2D Draft 화면: 작도/스냅/치수 → 저장(새 Revision)
  → [3D 필요?] ─예→ 폐곡선 선택 → Extrude/Revolve/Boolean → STEP 내보내기
  → 승인 요청 → (REVIEWER 승인) → RELEASED
```

### 3.2 견적 담당자: 자동 견적

```text
로그인 → 견적 요청 생성(고객·프로젝트) → 원천 도면 Revision 선택(DXF/STEP)
  → 메트릭 추출 결과 확인 → [재질/두께 누락?] ─예→ 입력
  → 자동 산출 → 견적 라인 검토 → [라인 클릭 → 도면 하이라이트로 근거 확인]
  → [조정 필요?] ─예→ 값+사유 입력(MANUAL)
  → 검증 → [ERROR?] ─예→ 수정 ─┐
  → 승인 요청 → REVIEWER 승인 → PDF/Excel 출력 → (ERP 전송)
```

### 3.3 관리자: 기준정보

```text
로그인 → 관리자 → 기준정보(재질/공정/임률/비율/레이어 매핑) → 새 버전 등록 → 적용일 지정
```
