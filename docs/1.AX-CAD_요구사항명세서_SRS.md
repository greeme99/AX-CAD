# AX-CAD 요구사항 명세서 (SRS) V1.0

> 7단계 개발 절차 중 **1단계 산출물**. `plan.md`의 W1(요구사항 정의) 단계 결과물이며, 게이트 **G1** 승인 대상이다.
> 근거: `plan.md`, `CLAUDE.md`, `Research/` 14개 문서, `.claude/rules/*`, `.claude/memory/MEMORY.md`

## 1. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 프로젝트명 | AX-CAD — 중견제조기업용 In-house CAD & 한국표준 자동 견적 시스템 |
| 작성일 | 2026-10-09 |
| 버전 | V1.0 (G1 승인 전 초안) |
| 작성자 | AX-CAD 개발팀 (Claude Code 보조 작성) |
| 개발 방법론 | Hybrid — 요구사항·아키텍처·3D 엔진 설계는 Waterfall, 세부 기능·견적 로직은 Agile Sprint |
| 개발 순서 | 2D CAD(R1) → 3D CAD(R2) → 견적(R3) → BOM·ERP 연계(R4) |

**한 문장 문제 정의**
> 설계 도면(DXF/STEP)에서 견적까지의 과정이 사람 손으로 다시 측정·입력되어 느리고 근거가 남지 않으므로, 사내 CAD에서 도면 형상을 직접 계측해 한국표준 원가 체계로 견적서를 자동 산출하고 그 근거를 도면 객체까지 추적할 수 있게 한다.

## 2. 배경 및 목적

### 2.1 현행 문제점

| 대상 사용자 | 현재 겪는 불편 |
|---|---|
| 설계·기술 엔지니어 | 상용 CAD 라이선스 비용 부담, 사내 기준(레이어·품번·재질)이 도면에 일관되게 들어가지 않음 |
| 영업·원가 견적 담당자 | 도면을 보고 절단길이·구멍 수·중량을 수기로 재고 엑셀에 옮겨 적음 → 시간 소요, 측정 누락, 담당자별 편차 |
| 생산·품질 관리자 | 견적 금액이 어떤 도면 요소·공정·단가에서 나왔는지 역추적이 불가능 |
| 경영/감사 | 수동 조정 이력이 남지 않아 견적 타당성 검증이 어려움 |

### 2.2 개선 목표

- 도면에서 견적 근거 데이터(절단길이, 면적, 구멍 수, 절곡 수, 블록 반복 수, 부피, 표면적)를 **자동 계측**한다.
- 한국표준 원가 체계(재료비·노무비·경비 → 일반관리비 → 이윤 → VAT)로 **견적서를 자동 산출**한다.
- 모든 견적 라인이 **원천 도면 객체 → 공정 규칙 → 단가 → 견적 라인**으로 역추적된다.
- 자동 산출값과 사람이 조정한 값을 **분리 저장**해 감사 가능하게 한다.

### 3.3 한국표준 원가 체계 (REQ-12 상세)

`.claude/rules/quote-engine.md` 기준.

```text
순제조원가   = 직접재료비 + 직접노무비 + 제조간접비
  직접재료비 = 정미중량(kg) × 재질단가(원/kg) × (1 + 스크랩률)
  직접노무비 = Σ(공정별 표준공수(h) × 임률(원/h))
  제조간접비 = Σ(공정별 기계시간(h) × 기계시간당 경비(원/h))   ※ 사내 기준에 따라 노무비 대비 비율로 대체 가능
총원가       = 순제조원가 × (1 + 일반관리비율)
견적공급가액 = 총원가 × (1 + 이윤율)
세액(VAT)    = 견적공급가액 × 10%
최종견적금액 = 견적공급가액 + 세액
```

> ⚠️ 일반관리비율(5~8%)·이윤율(7~15%)·절사 규칙은 **사내 기준 미확정**이다. G1 이전에 확보해야 한다(§4.3).

## 5. 성공 기준

### 5.1 정량 지표

| 지표 | 현재(기준선) | 목표 | 측정 방법 |
|---|---|---|---|
| 판금 부품 1건 견적 작성 시간 | W1에서 측정 (수기) | 기준선 대비 **70% 단축** | 실제 견적 10건 시간 측정 비교 |
| 메트릭 측정 오류(누락·오측) | W1에서 측정 | 샘플 도면 기대값 **100% 일치** | `tests/test_quote.py` 회귀 |
| 견적 금액 정확도 | — | 수기 검증 견적 3건과 **원 단위 일치** | 수락 테스트 |
| 견적 근거 추적률 | 0% | 견적 라인의 **100%**가 원천 객체 trace 보유 | DB 검증 쿼리 |
| 기하 정확도 | — | 부피·면적 상대오차 **≤ 1e-6** | `tests/test_geometry.py` |
| 스냅 반응성 | — | 1만 엔티티 **< 5ms** | 벤치 테스트 |

> 💡 "70% 단축"은 목표 가설이다. W1에서 기준선을 측정한 뒤 G1에서 확정한다.

### 5.2 정성 지표

- 견적 담당자가 "견적 근거를 도면에서 바로 확인할 수 있다"고 평가 (R3 리뷰 설문 4/5 이상)
- 설계자가 2D 작도·스냅 조작이 상용 CAD 대비 "업무 수행에 지장 없음" 평가
- 감사 시 수동 조정 내역을 별도 자료 없이 시스템에서 확인 가능

## 6. 용어 정의

| 용어 | 설명 |
|---|---|
| DXF | Drawing Exchange Format. AutoCAD 도면을 태그(그룹코드) 텍스트로 표현한 교환 포맷 |
| ezdxf | DXF를 읽고·쓰는 Python 라이브러리 |
| Modelspace / Paperspace | DXF의 실제 형상 공간 / 출력용 레이아웃 공간. 견적은 Modelspace 기준 |
| Block / INSERT | 재사용 도형 정의(Block)와 그 배치(INSERT). INSERT 수가 반복 수량이 된다 |
| Entity Handle | DXF 엔티티의 고유 ID. 견적 추적의 기준 키 |
| OCCT | OpenCASCADE Technology. 오픈소스 3D 기하 커널 |
| B-Rep | Boundary Representation. 면·모서리·꼭짓점으로 솔리드를 표현하는 방식 |
| Extrude / Revolve | 2D 단면을 직선 방향으로 밀어내기 / 축 기준 회전시켜 솔리드 생성 |
| Boolean (Fuse/Cut/Common) | 솔리드 합집합 / 차집합 / 교집합 |
| STEP AP242 | ISO 10303 3D 교환 표준의 최신 응용 프로토콜(형상·조립·PMI) |
| IGES | 구형 3D 교환 표준 포맷 |
| XDE | OCCT의 확장 데이터 교환 모듈(이름·색·레이어·조립구조 보존) |
| PMI / GD&T | 3D 모델의 제조 정보 / 기하공차 표기 |
| 스냅(Snap) | 커서를 도형의 특정 점(끝점·중점·중심)에 자석처럼 붙이는 기능 |
| 공간 인덱스 | R-tree·그리드 버킷처럼 근처 객체만 빠르게 찾는 자료구조 |
| 표준공수(M/H) | 공정 1회 수행에 필요한 표준 작업시간(Man-Hour) |
| 임률 | 시간당 노무 단가 |
| 정미중량 | 가공 후 부품의 순수 중량 |
| 스크랩률 | 재료 손실 비율 |
| Traceability(추적성) | 견적 라인 → 단가 → 규칙 → 원천 도면 객체로 거슬러 올라갈 수 있는 성질 |
| Override | 사용자가 자동 산출값을 수동 조정한 값 |
