# AX-CAD UAT 실행 가이드

> 대상: UAT를 진행하는 설계·견적·생산·관리자 담당자와 운영 지원 개발자.
> 시나리오 목록과 결과 기록은 `docs/7` §7(U-01~U-08)이 원본이다. 이 문서는 **준비 → 실행 → 기록** 방법만 다룬다.

## 요약

| 단계 | 내용 | 담당 |
|---|---|---|
| 0. 환경 | 개발 DB와 분리된 **UAT 전용 DB·파일 저장소**를 새로 만든다 | 개발 |
| 1. 계정·프로젝트 | 관리자 1명 → 역할별 사용자 → UAT 프로젝트·구성원 | 관리자 |
| 2. 기준정보 | G1 작성본 가져오기 → 내용 확인 → 확정(되돌릴 수 없음) | 견적·관리자 |
| 3. 실행 | U-01~U-08을 사내 실도면으로 수행 | 각 역할 |
| 4. 기록 | `docs/7` §7 결과 열 + 결함은 아래 양식 | 각 역할 → 개발 |

## 0. 환경 준비 (개발 담당)

### 0.1 개발 데이터를 지우지 않고 새 DB를 쓴다

개발 DB(`axcad`)에는 가짜 단가 기준정보, E2E 계정, 테스트 견적이 남아 있다. 감사 로그·확정 견적·확정 기준정보는 **DB 트리거로 삭제가 막혀 있어** 행 단위 정리가 불가능하다. 따라서 정리 대신 **UAT 전용 DB를 새로 만든다.** 개발 DB는 그대로 두어 비교·재현용으로 쓴다.

**배포 패키지(`deploy/`)로 설치한다** — 절차는 [`deploy/README.md`](../deploy/README.md) §2. 컨테이너마다 새 DB·파일 볼륨이 생기므로 개발 데이터가 섞이지 않는다.

```bash
cd deploy && cp env.example .env      # POSTGRES_PASSWORD·JWT_SECRET: openssl rand -hex 32
#   AXCAD_SUPPLIER_FILE=/config/supplier.json (deploy/config/ 에 실제 공급자 정보, 없으면 정식 견적서 409)
#   ERP_API_URL / ERP_API_TOKEN → 스테이징 ERP (U-07). 없으면 ERP 전송은 409 "미설정"
docker compose build && docker compose up -d
docker compose run --rm api python -m backend.cli create-user --login uat-admin --name "UAT 관리자" --admin
```

같은 서버에 운영과 UAT를 함께 둘 때는 프로젝트 이름과 포트를 나눈다: `docker compose -p axcad-uat up -d` + `.env`의 `AXCAD_PORT=8081`(볼륨도 `axcad-uat_*`로 따로 생긴다).

- 공급자 정보 파일 형식은 `backend/config/supplier.json`(샘플, `_sample` 키가 있으면 정식본 발행 거부)을 따른다. 실제 파일에는 `_sample` 키를 넣지 않는다.
- UAT 종료 후 DB를 버릴 때는 감사 증적 보존 여부를 먼저 결정한다(UAT 결과의 근거가 된다).

### 0.2 확인

| 확인 | 방법 |
|---|---|
| 스키마 최신 | `docker compose ps -a` → `migrate`가 exited (0), `docker compose run --rm migrate alembic current` → `(head)` |
| API 동작 | 브라우저에서 로그인 화면 표시, `uat-admin` 로그인 |
| 개발 데이터 비혼입 | 프로젝트 목록이 비어 있음, 기준정보 버전 없음 |

## 1. 계정·프로젝트 준비 (관리자)

메뉴 **사용자**(`/admin/users`)에서 아래 역할로 계정을 만든다. 한 사람이 여러 역할을 가질 수 있지만, **승인 시나리오(U-03·U-05)는 요청자와 승인자가 반드시 다른 사람**이어야 한다(자기 승인 차단이 검증 대상).

| 역할 코드 | UAT 담당 | 주요 시나리오 |
|---|---|---|
| DESIGNER | 설계 엔지니어 | U-01, U-02, U-03(요청), U-06 |
| REVIEWER | 설계·견적 검토자 | U-03(승인), U-05(승인), 감사 로그 |
| ESTIMATOR | 영업·원가 견적 | U-04, U-05(요청) |
| MANUFACTURING | 생산 관리 | U-06, U-07 |
| ADMIN | 관리자 | U-08 |

그다음 **프로젝트**(`/projects`)에서 UAT 프로젝트를 만들고, 프로젝트 화면에서 위 사용자들을 **구성원**으로 추가한다. 구성원이 아니면 도면·견적·감사 로그가 보이지 않는다(정상 동작).

## 2. 기준정보 준비 (견적·관리자)

1. 메뉴 **기준정보**(`/admin/master-data`) → 빈 버전 생성.
2. G1 작성본 엑셀 가져오기 → 시트 1~6 내용이 이 초안으로 들어간다.
3. 화면에서 재질 단가·공정 규칙·원가 비율을 원본 엑셀과 대조한다.
4. **확정(활성화)**: 이후 수정 불가. 바꾸려면 복사해 새 버전을 만든다. 확정 전에 3번을 끝낸다.

기준정보가 없으면 견적 메트릭은 기본 규칙으로 계산되고 금액 비교(U-05, TC-67)는 의미가 없다.

## 3. 시나리오 실행

공통 규칙:
- **사내 실도면**을 쓴다(합성 도면은 개발 테스트에서 이미 검증됨). 기밀 도면은 UAT 환경 밖으로 내보내지 않는다.
- 각 시나리오는 "확인 기준"을 하나라도 못 맞추면 Fail로 기록하고 결함을 남긴다.
- 화면 캡처는 결함 재현에 필요한 범위만 남긴다(단가·고객명 노출 주의).

| # | 절차 (화면 경로) | 확인 기준 |
|---|---|---|
| U-01 | 프로젝트 → 도면 생성 → 도면 화면 **DXF 업로드** → 개정 행에서 뷰어 열기 → 선·원 작도, 이동, 치수 추가 → 저장 | 레이어·치수 표시, 저장 시 새 리비전(A→B), 잠긴 레이어 객체는 수정 불가 |
| U-02 | 도면 화면 → 3D 모델(`/model/<도면>`) → 스케치 Extrude·Revolve·Boolean, STEP 가져오기·내보내기 | 부피·면적 표시, 내보낸 STEP을 사내 CAD에서 다시 열 수 있음 |
| U-03 | 설계자: 도면 화면 **승인 요청**(승인자 지정) → 검토자: **승인함** → 승인 또는 반려(사유) | 상태 전이(초안→검토 중→승인/반려), 본인 승인 불가, 승인 전 외부 배포 내보내기 차단 |
| U-04 | 견적 담당: 뷰어 **견적 메트릭** → 견적 생성 → 견적 화면에서 라인 클릭(추적 드로어) → 단가·공수 수동 조정(사유) | 라인별 근거(원천 엔티티 → 규칙 → 단가), 원천 하이라이트, 조정값과 자동값이 따로 보임 |
| U-05 | 견적 담당: 승인 요청 → 검토자: 승인 → 정식 견적서 PDF·Excel 발행 | 수기 견적과 **원 단위** 일치(TC-67), 공급자 정보 실제 값, 정식본은 재발행해도 같은 파일 |
| U-06 | 조립 도면 업로드 → 도면 화면 **BOM** → BOM 생성 → 미매핑 블록에 품번 지정 → CSV 내려받기 | 블록 수량 = 실제 수량, 미매핑 표시, CSV를 엑셀로 열었을 때 수식 실행 없음 |
| U-07 | 승인된 도면의 BOM → ERP 전송 → **연동 작업**(`/admin/integrations`)에서 상태 확인, 실패 시 재시도 | 스테이징 ERP 수신, 같은 BOM 재전송 시 중복 생성 없음(멱등 키), 실패 3회 후 재시도 가능 |
| U-08 | 관리자: 사용자 비활성화·역할 변경, 구성원 추가·제외, 기준정보 가져오기 / 검토자: **감사 로그** | 역할별 메뉴 차이, 변경 이력 기록, 검토자는 자기 프로젝트 로그만 보임 |

## 4. 결과·결함 기록

### 4.1 결과

`docs/7` §7 표의 **결과** 열에 `Pass` / `Fail(UAT-xx)` / `보류(사유)`와 수행일·수행자 역할을 적는다.

### 4.2 결함 양식

| 항목 | 작성 예 |
|---|---|
| ID | UAT-01 (순번) |
| 시나리오 | U-04 |
| 심각도 | Critical(업무 불가·금액 오류) / Major(우회 가능한 기능 오류) / Minor(표시·문구) |
| 재현 절차 | 1) 도면 X 업로드 2) 견적 메트릭 3) … |
| 기대 결과 | 절단 길이 1,234.5mm |
| 실제 결과 | 1,200.0mm |
| 첨부 | 도면 파일명·리비전 ID, 화면 캡처(민감정보 가림) |
| 환경 | 브라우저(Chrome/Edge 버전), 해상도 |

- **금액 차이**는 견적 화면의 추적 드로어(원천 → 규칙 → 단가)를 캡처해 함께 남긴다. 수기 견적서와 같은 줄끼리 비교한다.
- 지원 브라우저는 Chrome·Edge 최신 2개 버전, 1280px 이상 데스크톱이다(NFR-06). 그 밖의 환경 문제는 Minor로 분류한다.

## 5. 종료 기준

`docs/7` §6 릴리스 판정 기준을 따른다: 해당 릴리스 UAT Pass 100%, Critical·Major 결함 0건. Minor 결함은 PO 승인 시 조건부 릴리스.
