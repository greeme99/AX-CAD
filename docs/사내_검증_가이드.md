# AX-CAD 사내 검증 가이드 (서버 설치 → 성능 → 기준정보 → ERP → UAT)

> 대상: 사내 서버에 AX-CAD를 올리고 실데이터로 검증하는 IT·설계·견적·ERP 담당자.
> 개발 환경에서 할 수 있는 검증은 끝났다(`docs/7` Pass 87/92). 남은 검증은 **사내 서버·실도면·실데이터**가 있어야 하므로 이 문서대로 사내에서 수행하고, 결과(숫자·오류·차이)만 개발 담당에게 전달한다.
> 사내 서버: Linux x86_64 + Docker, 사내 CA 없음(자체 서명 HTTPS), 인터넷 가능 — 2026-10-10 확정.

## 요약

| 순서 | 검증 | 필요한 것 | 담당 | 소요 | 개발 담당에게 보낼 것 | TC |
|---|---|---|---|---|---|---|
| ① | 서버 설치·HTTPS 리허설 | 서버, 저장소 접근 권한 | IT | 1~2시간 | §1 체크리스트 OK/NG | TC-101·106 |
| ② | 실도면 성능 측정 | ①의 서버, 실도면 DXF 10개 이상 | IT·설계 | 30분 | `NFR-02 real` 줄 | TC-97 |
| ③ | 공급자 정보 | 회사 정보 | 영업·관리 | 15분 | 정식 견적서 OK/NG | 정식 견적서 |
| ④ | G1 기준정보·샘플 비교 | G1 작성본, 샘플 도면 | 견적·설계 | 반나절 | 가져오기 오류, 기대값/실제값 차이 | TC-60·64·67 |
| ⑤ | ERP 연동 | ERP 사양, 스테이징 ERP | ERP 담당 | 사양 확정 후 1~2일 | §5 사양 체크리스트 답변 | TC-93~96 |
| ⑥ | UAT | ①~④ 완료, 역할별 담당자 | 현업 | 1~2주 | U-01~08 결과, 결함 | R4 판정 |

**원칙**: 단가·도면·고객명은 사내 서버 밖으로 내보내지 않는다. 개발 담당에게는 숫자·차이·오류 메시지만 보낸다(토큰·비밀번호·키는 보내지 않는다).

## 1. 서버 설치·HTTPS 리허설

이 서버를 그대로 UAT 서버로 쓸 수 있다. 운영 서버는 UAT 뒤 새로 설치하거나 `-p axcad-uat`로 분리한다(`docs/UAT_가이드.md` §0).

**사전 준비**: 서버에서 저장소 clone 권한(배포 키 또는 토큰), 서버 이름(사내 DNS 등록, 없으면 IP만으로도 접속 가능), 사용자 PC → 서버 443 방화벽 허용.

```bash
# 1) 설치 (sudo 가능한 계정)
git clone https://github.com/greeme99/AX-CAD.git /opt/axcad && cd /opt/axcad/deploy
cp env.example .env && chmod 600 .env
for k in POSTGRES_PASSWORD APP_DB_PASSWORD JWT_SECRET; do
  sed -i "s/^$k=.*/$k=$(openssl rand -hex 32)/" .env
done
# 2) HTTPS 인증서 — 출력되는 SHA256 값을 적어 둔다
sudo ./tls-selfsigned.sh axcad.<회사도메인> <서버 IP>
# 3) 빌드·기동 (최초 빌드 5~10분)
docker compose build && docker compose up -d
docker compose ps                      # migrate: exited (0), api·db: (healthy)
# 4) 관리자 (비밀번호를 화면에서 두 번 입력)
docker compose run --rm api python -m backend.cli create-user --login admin --name "관리자" --admin
# 5) 점검
./check-app-role.sh                    # "app role ok ..."
curl --cacert config/tls/server.crt https://<서버 IP>/api/health    # {"status":"ok"}
```

**PC 인증서 등록 (시험 PC 1대 → 확인 후 그룹 정책으로 전체 배포)**

1. 서버의 `deploy/config/tls/server.cer`를 PC로 복사한다.
2. 명령 프롬프트: `certutil -hashfile server.cer SHA256` → 2)에서 적은 값과 같은지 확인.
3. 관리자 명령 프롬프트: `certutil -addstore -f Root server.cer` → 브라우저 재시작.
4. `https://axcad.<회사도메인>` 접속.

자세한 등록·해제·갱신 절차는 `deploy/README.md` §2-1·§4.

**체크리스트**

| # | 확인 | 기대 결과 | OK/NG |
|---|---|---|---|
| 1 | `docker compose ps` | migrate exited (0), api·db (healthy) | |
| 2 | `./check-app-role.sh` | "app role ok" | |
| 3 | 등록 안 한 PC의 Chrome | "연결이 비공개로 설정되어 있지 않습니다" 경고 | |
| 4 | 등록한 PC의 Chrome·Edge | 경고 없이 로그인 화면 | |
| 5 | 등록한 PC의 Firefox(사용 시) | `about:config` → `security.enterprise_roots.enabled`=true 후 경고 없음 | |
| 6 | `http://<서버>:8080` | https로 자동 이동 | |
| 7 | 관리자 로그인 → 프로젝트·도면 생성 → DXF 업로드 → 뷰어 | 도면 표시 | |
| 8 | `./backup.sh` | `backups/`에 `.dump`·`.tar` 생성 | |

## 2. 실도면 성능 측정 (NFR-02)

**사내 서버에서 측정한다**: 목표는 운영 서버 기준이어야 하고, 도면도 사내망을 벗어나지 않는다. 사용자가 없는 시간에 한다.

**도면**: G1 7 시트 샘플 + 현업 최대 크기 도면 포함 **10개 이상**을 `/opt/axcad/docs/inputs/private/perf/`에 복사한다(git 제외 폴더, `.dxf`만 측정).

```bash
cd /opt/axcad
sudo apt-get install -y libgl1                     # 3D 커널(OCCT) 의존 라이브러리
curl -LsSf https://astral.sh/uv/install.sh | sh    # uv (Python 자동 설치), 새 셸에서 이어서
docker run -d --name axcad-perfdb -e POSTGRES_USER=axcad -e POSTGRES_PASSWORD=axcad-perf \
  -e POSTGRES_DB=axcad_test -p 127.0.0.1:5433:5432 postgres:16
uv sync
TEST_DATABASE_URL=postgresql://axcad:axcad-perf@localhost:5433/axcad_test \
JWT_SECRET=perf-only-secret-0123456789abcdef0123456789 \
AXCAD_PERF=1 AXCAD_PERF_DIR=docs/inputs/private/perf \
uv run pytest -s tests/test_perf.py -k real
docker rm -f axcad-perfdb                          # 측정용 DB 삭제
```

출력(파일명 없이 번호만):

```
NFR-02 real #1: 3.21 MB, 18234 entities/error, 2.45 s
...
NFR-02 real summary: 12 files, p50 1.80 s, p95 6.10 s, max 7.20 s, largest 9.80 MB in 7.20 s
```

**보낼 것**: `NFR-02 real` 줄 전체. 개발 담당이 p95 × 1.5로 업로드 목표를 제안하고 SRS·TC-97을 갱신한다(`docs/7` §2.5).

## 3. 공급자 정보 (정식 견적서)

1. 서버에 `deploy/config/supplier.json`(권한 644)을 만든다. `_sample` 키는 넣지 않는다.

   ```json
   {
     "company": "(주)회사명", "business_no": "123-45-67890", "ceo": "대표자",
     "address": "주소", "phone": "031-000-0000", "email": "sales@회사.co.kr",
     "validity_days": 30, "delivery": "발주 후 14일",
     "payment": "납품 후 익월 말 현금 결제", "note": "운송비 별도"
   }
   ```

2. `.env`에 `AXCAD_SUPPLIER_FILE=/config/supplier.json` 추가 → `docker compose up -d`.
3. 확인: 승인된 견적 → 정식 견적서 PDF 발행 → 머리말의 회사 정보. 공급자 파일이 없거나 사업자번호가 `000-00-00000`이면 발행이 거부되는 것이 정상이다.

## 4. G1 기준정보 + 샘플 비교

**4-1. 작성 (견적 담당)**: 기준정보(`/admin/master-data`) → **빈 G1 양식 내려받기** → 1~6 시트(재질·공정·임률·원가비율·레이어·표제란) 작성. 비고가 `예시`로 시작하는 행은 가져오지 않는다. 7 시트(샘플 기대값)·8 시트(수기 견적 3건)는 정답지로 따로 보관한다. 작성본은 기밀이다(`docs/inputs/README.md`).

**4-2. 가져오기 (견적·관리자)**: 기준정보 → 새 버전 → **G1 엑셀 가져오기**(오류는 시트·행 단위 표시) → 화면 값과 원본 대조 → **활성화**. 활성화는 되돌릴 수 없으므로 대조를 끝낸 뒤 한다.

**4-3. 비교 (설계·견적)**

| TC | 방법 | 판정 |
|---|---|---|
| TC-60 | 샘플 도면 업로드 → 뷰어 **견적 메트릭** → 7 시트 기대값과 비교 | 허용 오차 이내 |
| TC-64 | 같은 도면의 표제란(품번·재질·두께·수량) 추출값 | 6 시트 규칙대로 인식 |
| TC-67 | 8 시트 3건을 같은 도면으로 견적 생성 → 수기 견적과 비교 | 원 단위 일치 |

**보낼 것**: 가져오기 오류(시트·행·메시지), 차이 항목의 "기대값 / 실제값", 금액 차이는 견적 화면 추적 드로어(원천 → 규칙 → 단가) 캡처(단가는 가려도 된다). 개발 담당이 원인(규칙·단가·절사)을 찾아 수정한다.

## 5. ERP 연동

**ERP 담당에게 받을 사양**

| 항목 | 질문 |
|---|---|
| 엔드포인트 | 스테이징·운영 URL (https 필수) |
| 인증 | Bearer 토큰인가, API Key·OAuth2인가 |
| 데이터 형식 | 아래 `ax-cad.bom.v1`을 그대로 받을 수 있는가, 필드명·구조 변환이 필요한가 |
| 중복 방지 | `Idempotency-Key` 헤더(같은 BOM 재전송 시 중복 생성 방지)를 지원하는가 |
| 응답 | 성공·실패 코드, 재시도해도 되는 오류(5xx·429) 구분 |
| 품번 | AX-CAD 품번 ↔ ERP 품목코드 매핑 방법 |

현재 전송 형식:

```json
{ "schema": "ax-cad.bom.v1", "idempotency_key": "BOM:12:34", "bom_no": "...", "project_code": "...",
  "document": { "doc_no": "...", "title": "...", "revision_no": 2, "source_type": "DXF" },
  "items": [ { "item_no": 1, "part_no": "...", "part_name": "...", "qty": 4, "unit": "EA", "level": 1 } ] }
```

**시험**: `.env`에 `ERP_API_URL=https://<스테이징>`, `ERP_API_TOKEN=<토큰>` → `docker compose up -d` → 승인된 도면의 BOM에서 **ERP 전송** → **연동 작업**(`/admin/integrations`)에서 상태 확인 → 같은 BOM 재전송 시 ERP에 중복이 생기지 않는지 확인.

**보낼 것**: 위 사양 답변(토큰 값 제외). 형식이 다르면 개발 담당이 `backend/api/routes_erp.py::_payload`를 맞춘다.

## 6. UAT

①~④가 끝나면 `docs/UAT_가이드.md`대로 진행한다: 역할별 계정(요청자와 승인자는 다른 사람) → U-01~U-08 → 결과는 `docs/7` §7, 결함은 UAT 가이드 §4.2 양식. 종료 기준은 UAT Pass 100%, Critical·Major 결함 0건.

## 7. 권장 일정

1. 첫날: ① 설치 리허설 → 같은 서버에서 ② 성능 측정
2. 병행: G1 양식 작성 시작, ERP 담당에게 §5 사양 질문 전달
3. G1 완료 후: ③ → ④ → UAT 일정 확정
