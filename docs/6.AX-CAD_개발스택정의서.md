> 7단계 개발 절차 중 **6단계 산출물(개발 명세)**. 소스코드 자체는 `plan.md`의 스프린트(S1~S12)에서 작성하며, 이 문서는 그 기준(스택·구조·보안·순서·작업 지시 방식)을 고정한다.
> 근거: `CLAUDE.md` Stack/Architecture/Commands, `.claude/rules/*`, Research `P-견적생성확장4·5`(폴더 구조), `P-개발참조3`(CI·보안).

## 2. 프로젝트 구조

`CLAUDE.md` Architecture를 기준으로 한다. 아래는 R1~R4 동안 생길 파일의 **목표 구조**이며, 필요할 때 만든다(빈 폴더 선생성 금지).

```text
AX-CAD/
├── core/                          # 순수 도메인 로직 (FastAPI·DB 의존 없음 → 단독 pytest 가능)
│   ├── dxf/
│   │   ├── reader.py              # FN-01: 검증 + ezdxf 파싱 → EntityRecord 목록
│   │   ├── writer.py              # FN-07: 엔티티 → DXF
│   │   ├── metrics.py             # FN-14: 절단길이·구멍·절곡·면적·블록 전개
│   │   └── title_block.py         # FN-14: 표제란 추출
│   ├── geometry/
│   │   ├── sketch.py              # FN-10: 2D 엔티티 → Wire, 사전검증
│   │   ├── features.py            # FN-10/11: Extrude/Revolve/Boolean + ShapeFix
│   │   ├── exchange.py            # FN-12: STEP/IGES (XDE)
│   │   ├── measure.py             # FN-15: 부피·면적·BBox
│   │   └── tessellate.py          # FN-13: 메시 변환
│   ├── quote_engine/
│   │   ├── rules.py               # 규칙 YAML 로딩·검증
│   │   ├── costing.py             # FN-17: 한국표준 원가 계산 (Decimal)
│   │   ├── trace.py               # 추적 레코드 생성
│   │   └── validate.py            # FN-20
│   └── bom/
│       └── builder.py             # FN-23
├── backend/
│   ├── api/
│   │   ├── main.py                # FastAPI 앱, 라우터 등록, 예외 → 공통 응답
│   │   ├── deps.py                # DB 세션, 현재 사용자, 권한 체크
│   │   ├── schemas.py             # 공통 응답·요청 모델
│   │   └── routers/               # auth, projects, documents, files, drawings, geometry, quotes, master, approvals, bom, integrations, audit
│   ├── db/
│   │   ├── models.py              # SQLAlchemy 모델
│   │   ├── session.py
│   │   └── migrations/            # Alembic (트리거·뷰 포함)
│   ├── services/                  # 트랜잭션 경계: core 호출 + DB 저장 + 감사
│   └── workers/                   # 파싱·OCCT·PDF 작업 격리 프로세스
├── frontend/
│   └── src/
│       ├── app/                   # 정보구조도 §1 라우트
│       ├── components/
│       │   ├── ui/                # shadcn/ui (복사·소유)
│       │   ├── shell/             # AppHeader, AppSidebar, AppStatusBar, WorkbenchShell
│       │   ├── cad/               # CanvasViewport, ThreeViewport, ToolPalette, LayerTree, PropertyInspector, SnapOverlay, CommandPrompt, FeatureTree
│       │   └── quote/             # QuoteBuilder, SourceFilePanel, QuoteLineTable, QuoteSummaryCard, ValidationPanel, TraceabilityDrawer
│       ├── lib/                   # api.ts(fetch 래퍼), types.ts(OpenAPI 생성 타입), cad/(뷰 변환·스냅 인덱스·툴 상태머신)
│       └── store/                 # useCadStore, useQuoteStore, useAppStore
├── tests/
│   ├── fixtures/                  # 샘플 DXF/STEP(익명화) + expected/*.yaml 기대값
│   ├── test_dxf.py  test_geometry.py  test_quote.py  test_api_*.py  test_security_upload.py
├── docs/                          # 본 7단계 산출물, openapi.yaml, ADR
├── deploy/            # compose.yaml, api/web Dockerfile, nginx/, backup·restore 스크립트
├── .env.example
├── pyproject.toml
└── README.md
```

**계층 규칙**
- `core/` → 외부(FastAPI·SQLAlchemy) import 금지. 입력/출력은 dataclass·dict.
- `backend/services/` 만 DB와 `core/`를 함께 다룬다.
- `frontend/lib/cad/`는 화면 변환·선택·스냅 인덱스만 담당하며 기하 연산(면적·Boolean 등)은 하지 않는다(`.claude/rules/cad-geometry.md` §3).

| 출력 | `POST /api/quotes/{id}/reports`, `GET /api/reports/{id}` | FN-21 |

- 응답: `{success, data, error}`. 목록은 `data: {items, total, page, size}`.
- 프론트 타입은 FastAPI가 생성한 OpenAPI에서 자동 생성(`openapi-typescript` 등, W2에서 확정)해 수기 중복 정의를 피한다.

## 4. 보안 이행 사항

| 항목 | 이행 방법 |
|---|---|
| 시크릿 | DB·JWT·ERP 자격증명은 `.env`(커밋 금지) → `.env.example`에는 키 이름만 |
| AI 보조 개발 | 실제 키·사내 주소·고객명·실도면을 프롬프트에 넣지 않음. 샘플 도면은 익명화본 사용 |
| 더미 데이터 | 개발·테스트는 시드/픽스처 데이터만 사용 |
| 업로드 | 확장자·매직바이트·크기 화이트리스트, UUID 파일명 저장, XREF 미로드, 블록 깊이/개수 상한, 워커 타임아웃 |
| 경로 탈출 | 저장 경로는 서버가 생성, 사용자 입력 파일명은 메타데이터로만 저장 |
| SQL | ORM/바인딩 파라미터만 사용, 문자열 조합 SQL 금지 |
| 규칙 YAML | `yaml.safe_load`만 사용, 수식은 `eval` 금지 → 화이트리스트 연산자만 지원하는 소형 평가기(또는 미리 정의된 공식 함수) 사용 |
| 인증·인가 | JWT 만료 30분, 모든 라우터에 역할·프로젝트 멤버십 의존성 |
| 감사 | 감사 로그 테이블은 INSERT 전용 권한 |
| 리뷰 | AI 생성 코드는 사람이 리뷰. 파서·업로드·인증·연동 변경은 `security-reviewer` 필수 |

## 5. 개발 순서 (점진적 개발)

### 5.1 Waterfall 단계의 개발 작업 (W2~W3)

1. `git init` + 브랜치 전략(main/develop/feature), 커밋 규칙 합의 (현재 저장소는 git 미초기화)
2. `uv init`, `pnpm create next-app`, shadcn/ui 초기화
3. 디자인 시스템 토큰(`globals.css`) + 공통 쉘(AppHeader/Sidebar/StatusBar/WorkbenchShell)
4. FastAPI 골격 + 공통 응답/예외 핸들러 + 헬스체크
5. Alembic 초기 마이그레이션(정보구조도 §4) + 트리거
6. docker-compose(api, web, postgres) + CI(ruff, mypy, pytest, lint, typecheck, vitest)
7. W3 OCCT PoC: `tests/test_geometry.py::test_extrude_step_roundtrip`

### 5.2 스프린트별 구현 단위

| 스프린트 | 구현 순서 (커밋 단위) |

### 5.3 기능 단위 지시 공식 (AI 보조 개발용)

> **현재 상태 → 수정 목표 → 변경 범위 → 금지사항 → 완료 기준**

예시 (S8, FN-14 블록 전개):

```text
현재 상태 : core/dxf/metrics.py는 modelspace의 LINE/ARC/CIRCLE 길이만 합산한다. INSERT는 무시된다.
수정 목표 : INSERT를 Insert.virtual_entities()로 재귀 전개해 절단길이·구멍 수에 반복 수량을 반영한다.
변경 범위 : core/dxf/metrics.py, tests/test_quote.py (다른 파일 수정 금지)
금지사항 : 새 의존성 추가 금지, ezdxf 내부 API(_로 시작) 사용 금지, 중첩 깊이 무제한 재귀 금지(최대 16)
완료 기준 : tests/fixtures/bracket_array.dxf 기대값(구멍 24개, 절단길이 3,840.00mm)과 일치,
            uv run pytest tests/test_quote.py 통과, ruff/mypy 통과
```

### 5.4 커밋·리뷰 규칙

- 커밋 단위: 위 표의 화살표(→) 하나 = 커밋 1개 이상. 테스트와 구현은 같은 커밋.
- 메시지: `feat(dxf): expand INSERT blocks in metrics (FN-14)` 형식, FN/REQ ID 포함.
