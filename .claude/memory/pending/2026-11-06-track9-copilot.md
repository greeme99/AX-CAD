- **13 R2.0 보완 + AI Copilot**(Track 9, 2026-11-06 사용자 결정·grill-me): 조립은 ASSEMBLY 문서가 PART 결과 몸체를 인스턴스로 참조(부품 200개 이내), 판금은 베이스·모서리 플랜지 + K-factor 해석 전개 + 레이저/절곡 견적, 자동화는 수식 파라미터 블록(일반 블록 + XDATA) + 명령 스크립트 + 앱 밖 Python SDK(앱 안 임의 코드 실행 금지). Copilot은 모든 화면 우측 패널(헤더 버튼·Ctrl+.)·규칙 기반(DFM·견적 조언·자연어 명령·도움말), LLM은 Gemini 2.5 Flash 접점만 두고 기본 꺼짐·관리자 키 설정 시에만·요약 문맥(화면·문서 유형·피처 개수·코드)만 전송. 순서 Q1 Copilot → Q2 조립 → Q3 판금 → Q4 자동화 → Q5 통합. 근거 `plan.md` §15.
- 교훈(Q1): 2D 명령을 여러 개 이어서 `submit`하면 React 상태가 갱신되기 전 값을 참조한다 → 입력열은 `lib/cad/script.ts runInputs`로 순수하게 이어 돌리고 결과를 한 번에 적용한다(실행 취소 1단위).
- 교훈(Q1): DRAWING 문서에도 3D 피처가 생긴다(DXF → 3D). 문서 단위 점검은 doc_type으로 갈라 한쪽만 보지 말고 도면·모델 둘 다 본다.
- 교훈(Q2, 조립 솔버): 면 마주봄 잔차를 `na+nb`로 두면 법선 방향 성분이 해 근처에서 2차라 가우스-뉴턴이 거대한 스텝을 요구한다 → 올바른 쪽에서는 `na×nb`. 최소 노름 스텝은 mm와 rad를 같은 무게로 봐 부품을 기울여 간격을 메운다 → 회전 변수를 부품 크기로 스케일. 같은 방향 평면끼리 '일치'는 안장점 → 풀기 전에 자유 부품을 뒤집는다. 체인 20개 이상으로 시험해야 드러난다(2~5개는 모두 수렴).
- 결정(Q3, 판금): 전개는 임의 B-Rep 펼치기가 아니라 판금 피처 파라미터(외곽 + 변별 플랜지)에서 해석식으로 만든다(BA = θ·(R+K·T)) → 정확·빠름, 대신 1단 플랜지·직선 외곽만. 플랜지 길이 L은 굽힘 뒤 직선부. 판금 몸체 견적 소재는 판재(전개 BBox + 여유 × T).
- 결정(Q4, 자동화): 파라미터 블록의 템플릿·값은 XDATA가 아니라 BLOCK 설명(description, DXF 그룹 4)에 JSON 한 줄로 둔다(기존 `apply_edits` 블록 정의 경로 재사용). 이 값은 파일에 그대로 쓰이므로 서버가 파라미터 블록 JSON만·제어문자 없이 받는다(BUG-58: 개행이면 DXF 그룹 주입). 앱 안 코드 실행 없이 `.axs`는 기존 명령 리듀서, SDK는 앱 밖 REST(표준 라이브러리, 리디렉션 미추종·설치 토큰은 루프백만).
- 교훈(Q4): API 목록이 내장 템플릿을 검증 전 원본으로 내보내 선택 키(`states`)가 빠졌고, 화면이 `t.states.length`에서 깨졌다 → 내보내는 것은 항상 검증·정규화된 값. 브라우저 확인에서만 드러났다(단위 테스트는 생성 경로만 봄).
- 교훈(Q5): 기능 단계별로 PR을 나누면 뒤 단계 커밋은 로컬에 쌓인다 → 단계마다 커밋을 나눠 두고, 머지 후 main 위에 cherry-pick + 원격 브랜치는 `-X ours` 병합(내용 변화 0 확인)으로 강제 푸시 없이 올린다. 앞 단계가 바꾼 기준 데이터(예: 공정 예시 행)는 다른 테스트의 하드코딩 값을 깨므로 전체 pytest를 단계마다 돌린다.
